# Graduated Evaluation Harness

Score implementation quality across four evaluation layers, producing a graduated quality score (0-100).

**Announce at start:** "I'm using the adev:eval skill to run the evaluation harness."

## Arguments

- `--spec <path>`: evaluate implementation of a specific spec (required)
- `--layer <N>`: run only a specific layer (1-4)
- `--configure`: interactive setup of eval configuration
- `--rubric <path>`: use a custom rubric for Layer 3

## Prerequisites

1. `.context-index/` must be initialized
2. `adev:validate` should have passed
3. For Layer 2, `.context-index/samples/` should have relevant golden samples
4. Eval config lives in `.context-index/evals/config.yaml` (generated by `--configure`)

## Layer 1: Deterministic Checks (Automated)

Run all quality gates from `governance/gates.yaml` or constitution fallback.

- Each gate produces pass/fail
- Layer 1 score = (gates passed / total gates) * 25
- Maximum: 25 points

## Layer 2: Architectural Conformance (Automated)

Compare implementation against golden samples and constitutional patterns:

1. **Pattern consistency (0-10):** Naming, structure, error handling
2. **Boundary compliance (0-5):** Run `boundaries.yaml` patterns
3. **Complexity metrics (0-5):** File sizes, function lengths
4. **Test quality (0-5):** Tests verify behavior, cover error cases

Layer 2 score = sum (0-25)

## Layer 3: LLM-as-a-Judge (AI-Assessed)

Dispatch reviewer subagent with rubric to score subjective dimensions:

1. **Readability (0-5):** Clear variable names, understandable flow
2. **Maintainability (0-5):** Easy to modify, concerns separated
3. **Spec fidelity (0-5):** Captures spirit of spec, handles edge cases
4. **Idiomatic usage (0-5):** Framework and language idioms
5. **Error handling (0-5):** Right level, useful messages, graceful degradation

Layer 3 score = sum (0-25)

## Layer 4: Human-in-the-Loop Checkpoints (Manual)

Surface items requiring human judgment:

1. Business logic correctness
2. UX review (if UI changes)
3. Security review (for auth/data/API changes)
4. Performance impact

User marks each: PASS (5), ACCEPTABLE (3), NEEDS_WORK (0)

Layer 4 score = (sum / max possible) * 25

## Scoring

**Total quality score = Layer 1 + Layer 2 + Layer 3 + Layer 4 (0-100)**

| Score | Grade | Interpretation |
|-------|-------|---------------|
| 90-100 | A | Excellent. Exemplary implementation. |
| 75-89 | B | Good. Minor improvements possible. |
| 60-74 | C | Acceptable. Notable gaps in quality. |
| 40-59 | D | Below standard. Significant issues. |
| 0-39 | F | Failing. Major rework needed. |

## Report Format

Write to `.context-index/evals/<spec-slug>-eval.md`:

```markdown
# Evaluation Report: <Spec Title>

> **Date:** YYYY-MM-DD
> **Spec:** <path>
> **Overall Score:** N/100 (Grade: A-F)

## Layer 1: Deterministic Checks — N/25
- Tests: PASS/FAIL
- Lint: PASS/FAIL
- Typecheck: PASS/FAIL

## Layer 2: Architectural Conformance — N/25
- Pattern consistency: N/10
- Boundary compliance: N/5
- Complexity metrics: N/5
- Test quality: N/5

## Layer 3: LLM-as-a-Judge — N/25
- Readability: N/5 — <justification>
- Maintainability: N/5 — <justification>
- Spec fidelity: N/5 — <justification>
- Idiomatic usage: N/5 — <justification>
- Error handling: N/5 — <justification>

## Layer 4: HITL Checkpoints — N/25
- Business logic: PASS/ACCEPTABLE/NEEDS_WORK
- UX review: PASS/ACCEPTABLE/NEEDS_WORK/SKIPPED
- Security review: PASS/ACCEPTABLE/NEEDS_WORK/SKIPPED
```

## Configuration

Interactive setup creates `.context-index/evals/config.yaml`:

```yaml
layers:
  deterministic: true
  architectural: true
  llm_judge: true
  hitl: false  # opt-in

thresholds:
  minimum_score: 60
  exemplary_score: 90

rubric: default
```

## Integration

- `adev:validate` is the prerequisite (pass/fail gate)
- `adev:retro` reads eval scores for quality trend analysis
- `adev:sample` candidates identified from A-grade evaluations
- `adev:hygiene` includes eval score trends in drift report
