## Why the remaining seven generalize

`repomap`, `document`, `deploy`, `learn`, `eval`, `assess`, `using-adev` were not each given an independent fresh-copy pass in this session. The infrastructure being checked (1–5, 8) is **shared code**, exercised identically regardless of which scenario invokes it:

- **Setup (checks 1, 3)** — every scenario's Setup section is the same three-step boilerplate calling the same `scripts/eval-scenario-setup.mjs` functions (`createScenarioCopy`/`createOutputsRoot`/`spliceDbPath`). Confirmed by diffing scenario files directly (`diff scenarios/codehealth.md scenarios/deploy.md`): the Setup, Working directory, Containment, Environment, Manifest fidelity, Multi-worktree check, and Teardown sections are byte-identical boilerplate across scenarios; only the Run/Prerequisite/Writer-mechanism section differs per skill. The splice mechanism itself has its own exhaustive unit proof in Task 4 (`tests/lib/evals/rubric-coverage.test.mjs`, the `spliceDbPath` refusal-set tests), independent of which scenario calls it.
- **Door predicates (check 2)** — a pure filesystem walk (`readdirSync` + regex over `.md` files, checked for `.claude`/`.mcp.json`) with no skill-specific branch; the four fresh runs exercised it against four different copy trees built from the same fixture project, and it behaved identically each time.
- **Write-escape capture (check 4)** — reads `git worktree list --porcelain` from the real cwd once per scenario and diffs `git status`/`HEAD`; this has no dependency on what the scenario itself does, only on whether the scenario stays inside its own copy. The four fresh runs prove the harness-level mechanism is sound.
- **`artifact:` re-resolution (check 5)** — `lenientRealpath` + `isContained`, applied per rubric's own `artifact:` tokens; exercised against four different token sets (`CLAUDE.md`/`AGENTS.md`; `tasks.json`; none; three prototype paths) covering both the "tokens present" and "no tokens" cases.
- **Teardown (check 8)** — `cleanupTempDir()` on exactly the two `mkdtempSync` roots; identical call in all four runs, confirmed via `find <tmpdir> -newermt '-10 minutes'` returning nothing after each run and `lsof -nP -iTCP:3210-3219 -sTCP:LISTEN` returning nothing.

Checks 6 (board containment) and 7 (prototype teardown) are **not** shared — they are scenario-specific (only `issues` touches the board; only `prototype` runs a server) — and both were exercised directly above, not generalized from another scenario.

**What this pass does NOT claim:** it does not re-verify `repomap`'s, `document`'s, `deploy`'s, `learn`'s, `eval`'s, `assess`'s, or `using-adev`'s semantic rubric content, or their skill output. That verification already happened in Tasks 5–8 against real, live-exercised skill behavior (see below).
