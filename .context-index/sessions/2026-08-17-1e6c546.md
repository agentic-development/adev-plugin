## Intent

chore(governance): adopt per-reviewer context packs in review.yaml

`.context-index/governance/review.yaml` was materialized 2026-08-15T19:35:30,
one day before PR #279 (commit 631a12ad) changed the software domain's
reviewers from `context_pack: base` to architecture / security / consistency.
The write-once `materialized_at` marker means `adev governance materialize`
cannot re-derive it — a second run preserves existing entry bytes, confirmed
by `--dry-run` reporting "already explicit / newly written: (none) /
(no change)". So the project kept running the pre-PR assignment.

Effect before this change, measured by rendering `base` for a real target:
exactly two fenced sections (constitution.md, platform-context.yaml), 8854
bytes. No parent charter, no sibling specs, no ADRs, no cross-cutting specs.
Every review in this repo was reviewing against the constitution alone.

Changes only the `context_pack:` value on three entries already on disk.
Adds and removes nothing, and preserves each entry's `source: domain:software`
provenance — so this is a field edit, not the row-copy docs/governance.md
warns against.

This does NOT fully fix reviewer context. With the packs assigned, the
262144-byte cap now drops 29-71% of matched files (architecture 10/34,
security 12/36, consistency 49/69). The security pack loses exactly the two
governance files that distinguish it from architecture, making the two packs
functionally identical. Tracked as adev-plugin-j7pq.6, which proposes
delivering a path manifest instead of inlined bodies.

Also committed here, as consequences rather than intent:

- `explicit-governance-registries.spec.md` gained `drift_detected: true` and
  its log gained a `code_drift_detected` event. review.yaml is in that spec's
  source-manifest, so the write-time hook fired correctly. Clearing the flag
  is /adev:validate's on operator opt-in per ADR-0011, not a hand edit.
- The rev-5 amendment's lifecycle log. Its `review` step is deliberately left
  OPEN: the review was started and is genuinely pending, blocked on j7pq.6.
  Emitting `step_failed` would record the spec as having failed review when
  the defect is in the review tooling.
