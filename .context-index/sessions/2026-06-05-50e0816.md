## Intent

fix(lifecycle-state): self-derive plugin root for severity stamping

reportReviewer/reportValidator resolve severity via _resolveActorSeverity →
loadDomainConfig, which needs the plugin root to find bundled
templates/domains/<domain>/. The `adev report` CLI never threads a plugin
root, so the lib fell back to repoRoot; in any consumer repo that path has
no templates/, loadDomainConfig returned null, and every reviewer/validator
event degraded to severity "warning" (with DOMAIN_CONFIG_DEGRADED) —
regardless of the domain's severity_cap. A blocker finding was silently
recorded as a warning.

Fix at the resolution layer: derive the plugin root from this module's own
location (lib/ and templates/ are siblings), mirroring
lib/extensions/content-install.mjs. This corrects every caller (CLI,
programmatic, tests) without touching the dispatch contract. An explicit
pluginRoot still wins, preserving the genuine-failure degrade path.

The report's proposed CLI fix (args.pluginRoot = process.env.ADEV_ROOT) does
not apply: ADEV_ROOT is a skill-prose placeholder, not a runtime env var, so
it would have been a silent no-op.

Defect B (severity stamper ignores governance/review.yaml + gates.yaml
overrides that the dispatch path honors) is tracked separately as issue-542.
