## Intent

fix(build): remove broken blocker-fix loop — write sidecar + fail loud

Sibling to issue-527 — same /adev:specify --revise / --blocker-context
flag combination, different code path (review BLOCK recovery, not Step 0
specify-skip).

Before: when /adev:review-specs returned BLOCK, skills/build/SKILL.md
Step 1's Blocker-Fix Loop dispatched a specify subagent with
"--revise --blocker-context <fenced findings>". Neither flag exists on
/adev:specify. Standard-mode fall-through would re-author over the
existing spec without overwrite guards.

Fix: drop the auto-retry path entirely. On BLOCK in --full mode the
orchestrator now:

  1. Extracts blocker findings from .review.md
  2. Serializes them as a fenced markdown block (SEC-1: prompt-injection
     guard from prior contract is preserved)
  3. Writes the block to <spec-stem>.blockers.md sidecar (mirrors the
     <spec-stem>.routing.md pattern from issue-525's recommended /adev:route
     sidecar)
  4. Records the review step failed with verdict: BLOCK and error pointing
     at the sidecar
  5. Stops the build with a clear manual-revision-required message

The build.max_review_retries config slot is preserved for forward-compat
but now defaults to 0 and emits a warning + behaves as 0 when set > 0.
Auto-retry will be re-enabled when /adev:specify gains a real revision
workflow (separate enhancement; see issue-525 family for the related
plan-mutability discussion).
