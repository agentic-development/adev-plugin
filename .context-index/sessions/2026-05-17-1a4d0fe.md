## Intent

fix(validation): validator severity resolves from validate.yaml, not gates.yaml

_resolveActorSeverity in lib/lifecycle-state.mjs previously consulted
gates.yaml to look up validator severity. But gates.yaml carries command
gates (e.g., `test`, `lint`), not validator IDs — so every validator event
emitted by /adev:validate surfaced an UNKNOWN_VALIDATOR_DEFAULTED warning
even when the project's governance/validate.yaml correctly declared the
check's severity.

Fix: point the validator-severity lookup at validate.yaml (the single-
source-model artifact) rather than gates.yaml. Validate.yaml's `checks[]`
list already exposes per-check `severity`, so no schema change is needed.

Change is two constant updates:
- ACTOR_CONFIG_TYPE.validator:      'gates'  → 'validate'
- ACTOR_CONFIG_LIST_KEY.validator:  'gates'  → 'checks'

ACTOR_CONFIG_SEVERITY_FIELD.validator stays 'severity' (same field name
in both files).

Tests:
- Updated _resolveActorSeverity test to assert validate.yaml-driven
  resolution for known validator IDs (error and warning severities).
- Added a new test covering unknown-validator fallback.
- Updated reportValidator integration test to use a real validate.yaml
  check ID.
- Full suite: 3157 pass, 0 fail, 2 todo (pre-existing).

Verified: emitting `adev report --type validator --validator
validate.check-2-spec-compliance` now produces NO warning (previously
triggered UNKNOWN_VALIDATOR_DEFAULTED on every emission).

Auto-stamped drift on 4 specs whose source-manifest covers
lib/lifecycle-state.mjs is correct hook behavior; included.

Closes issue-507 AC3 (the part that PR #130's surface change alone could
not close).
