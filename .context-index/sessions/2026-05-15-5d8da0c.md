## Intent

fix(plan-immutability): use first non-pending plan_task as cutoff; TZ-safe compare; skip on shallow CI checkout

Three bugs in the plan-file immutability detector that caused CI to fail
across the cli-driver-surface PR stack while passing locally:

1. Timezone-unsafe string comparison. The detector compared a git author
   date (local offset, e.g. `2026-05-14T13:50:08-03:00`) against a
   lifecycle event timestamp (UTC, e.g. `2026-05-14T15:00:21.415Z`)
   using lexicographic string comparison. Locally on a UTC-3 runner the
   strings sort to "13 < 15" (no violation); on a UTC CI runner git
   emits `2026-05-14T16:50:08+00:00` for the same instant, which sorts
   to "16 > 15" (false violation). Fixed by parsing both via Date and
   subtracting milliseconds.

2. Bootstrap commits flagged as modifications. The detector used the
   first `plan_task` `pending` event as the cutoff, but /adev:plan
   emits pending events during plan authoring — before the plan file
   is committed. Result: every plan's first commit registered as a
   "modification after planning started." Fixed by using the first
   non-pending event (`in_progress`/`done`/`failed`) as the cutoff —
   that marks implementation start, which is what the spec's
   "subsequently modified" wording actually targets (plan-task-events
   AC bullet 5: "not mutated ... after initial authoring").

3. Shallow CI checkout broke `git log -1`. The detector fell back to
   `mtime` when `git log` returned empty, but CI uses fetch-depth=1
   (actions/checkout@v4 default), so `git log -1 -- <plan-file>`
   returns nothing for files committed before HEAD, and `mtime` on a
   fresh checkout is *today's* timestamp — making every old plan
   appear "modified" hours/days after its cutoff. Two-part fix:
   - lib/plan-immutability.mjs: when inside a `.git` repo and `git
     log` returns empty, return null (skip the file) instead of
     falling back to mtime. mtime is only used when there's no .git
     at all (test fixtures, tarball installs).
   - .github/workflows/ci.yml: add `fetch-depth: 0` to actions/
     checkout so the immutability check has full history to inspect.
     Without this, the check would silently no-op on CI.

Violation fixture extended with an `in_progress` event so the
"violation fixture is detected" test still proves detection works
under the new semantics. Fixture has no `.git`, so mtime fallback
still applies for it.
