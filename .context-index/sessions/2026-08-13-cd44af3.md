## Intent

fix(issues): migrate status faithfully and read dependencies back

Two fidelity defects found by round-trip-checking a real 312-issue board
after the id-preservation fix. Both are now covered by that same check,
which reports zero mismatches across every field.

1. STATUS DROPPED ON CREATE (issue-fw00cl, P0)

`br create` has no status flag, so a non-open status needs a follow-up
call. The legacy-import path already did this for epics; create() did
not. Every migrated closed ISSUE landed open -- the board held 79 closed
items where 262 were expected, exactly the epic count, with all 183
closed issues arriving open. That is worse than an incomplete board:
`/adev:issues ready` would surface finished work as actionable and
re-closing it would be indistinguishable from progress.

Terminal states go through `br close`; br refuses terminal statuses on
`update`. That asymmetry is why this needs its own path rather than a
flag. Verified after the fix: 125 open / 183 closed / 4 deferred,
matching source exactly.

2. DEPENDENCIES NEVER READ BACK (issue-bum897, P1)

Not data loss -- the edges were written correctly (br reported
dependency_count: 2 on issue-628) -- but _toIssue() hardcoded
`dependencies: []`, so all 45 edges were invisible through list()/get().
`/adev:issues ready` is specified as "open AND unblocked" and filters on
this field, so every blocked issue reported as ready while the real
graph sat intact in the database.

_fetchEdges() resolves them in ONE `br show` call. br's list projection
carries only dependency_count, so endpoints need `br show` -- which
accepts many ids at once. Only items br says have edges are requested,
so a 300+ item board costs one subprocess rather than 300. br answers in
its own id namespace, so endpoints are mapped back to adev ids via
external_ref. Read-only and best-effort: a failure degrades to "no edges
known" rather than making the board unreadable.

The `edges` parameter is optional -- several callers have no edge data to
hand, and making it required would have broken them silently.
