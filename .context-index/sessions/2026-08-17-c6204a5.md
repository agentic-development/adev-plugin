## Intent

feat(review): reject manifest-pack reviewers whose profile cannot read files

Under 'delivery: manifest' a reviewer is handed file PATHS instead of file
bodies. A profile granting neither 'filesystem-read' nor 'search' would
receive a list it cannot open — a review that reports on nothing while
looking like it ran. Reject such a reviewer at LOAD, as an error.

The check runs as a second pass after mergePacks: the pack's resolved
delivery is not known inside the reviewer-validation loop, which finishes
before packs are merged. Hoisting mergePacks would reorder which errors
surface first, so the new code is appended instead and every pre-existing
error keeps its position.

Unreachable with bundled configuration — read-only grants both categories
and all three reviewer profiles extend it — so the tests construct a
custom project-level profile, deliberately read-only-compatible so the
pre-existing REVIEWER_PROFILE_POSTURE check admits it.
