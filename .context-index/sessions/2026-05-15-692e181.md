## Intent

fix(orchestration): unblock charter-mode builds with subagent dispatch

Four targeted fixes uncovered while running /adev:build --charter:

1. skills/build/SKILL.md — remove `context: fork` from the build
   orchestrator frontmatter. Forked execution contexts don't inherit
   the Agent tool, so the orchestrator could not dispatch any pipeline
   step. Orchestrators must run inline in the parent session to retain
   subagent-dispatch capability (workers fork, coordinators don't).

2. lib/build-state.mjs — recordStepResult never cleared a prior
   build-level "failed" status when stale failed steps were overwritten.
   Recalculate from all current step statuses (anyFailed check) so
   resumed/auto-overwrite recovery actually unlocks downstream steps.

3. lib/lifecycle-state.mjs — priorStepOf treated `route` as a hard
   predecessor of `implement`, but the build SKILL.md documents route
   as "optional/observational". Added OPTIONAL_GATE_STEPS and made
   priorStepOf walk past optional steps, aligning the lib with the
   documented pipeline.

4. skills/validate/SKILL.md — preflight gate called
   `requireGate(state, "implement", ...)` thinking it would check
   implement completion, but the lib treats the arg as "step about to
   begin" and resolves the prior internally. Corrected to
   `requireGate(state, "validate", ...)` per the lib contract; the
   same inverted-arg pattern in skills/build/SKILL.md's gate-mapping
   comment is left for a future cleanup.
