## Intent

feat(validation): add validate-config migration to adev migrate

- New migrateValidateConfig(projectRoot, options) in
  lib/migrate-state-artifacts.mjs with three branches:
    * absent  → resolve domain from manifest (default 'software'), call
      loadDomainConfig(domain, 'validate', ...), copy starter bytes to
      .context-index/governance/validate.yaml. Falls back to 'software' when
      the resolved domain ships no starter, with a DOMAIN_STARTER_FALLBACK
      advisory.
    * present + valid  → no-op; reports 'already migrated'.
    * present + malformed  → throws MIGRATION_BLOCKED_BY_CORRUPT_CONFIG;
      the tool NEVER overwrites a malformed-but-customized file (SEC-5).
- Wire 'validate-config' into VALID_ARTIFACTS, ORDER, and the migrateAll
  dispatch. `adev migrate --artifact=validate-config` is now the public
  invocation.
- Update CLI help text to advertise the new artifact name.
- Tests cover: absent (writes), absent + dry-run, valid (no-op), malformed
  (refuses to overwrite), idempotency.
