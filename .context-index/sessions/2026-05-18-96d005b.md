## Intent

fix(cli-driver-surface): source-manifest verify recognizes H1-prefixed specs

`adev source-manifest verify --spec <path>` silently returned SKIP for any
spec whose first byte was not `---`. Most specs in this repo (133/204)
open with a `# H1` heading or HTML comment block before frontmatter, so
Check 1.5 in `/adev:validate` silently skipped 65% of the spec corpus —
manifest drift could land without being flagged.

Root cause: lib/cli/source-manifest.mjs::readManifestFromSpec was a
duplicate frontmatter parser that required `body.startsWith("---\n")`.
The lib already has a proven parser (`extractManifestFromFrontmatter`
in lib/source-manifest.mjs) that uses `/---\n([\s\S]*?)\n---/` and
correctly handles pre-frontmatter content.

Fix: delegate to the lib's parser. Deletes ~70 LOC of duplicate logic
and removes the unused `readFileSync` import. Adds a regression test
that constructs an H1-prefixed spec with a comment block before the
frontmatter and asserts the CLI returns PASS rather than SKIP.

After the fix, end-to-end CLI run on the originally-failing spec now
returns WARN (real source-manifest drift) instead of silent SKIP —
the check is doing its job for the first time on these specs.
