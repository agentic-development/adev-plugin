## Intent

fix(issues): close the beads claim gate's fail-open path

Three holes in the beads claim gate, all found by adversarial review of the
commit before this one rather than by its tests — which only ever exercised
the case where adev is the sole writer.

1. THE GATE FAILED OPEN. `claim()` evaluated requireClaimable against SIDECAR
   state while exclusivity lives in br's `assignee`. `br` is a user-facing
   CLI, so a human running `br update --claim` is ordinary usage, not an
   exotic race — and the sidecar knows nothing about it. requireClaimable saw
   "unclaimed", passed, br refused the write, and the adapter raised
   BEADS_COMMAND_FAILED → CLI exit 1 → which /adev:implement and /adev:debug
   explicitly treat as "warn and continue". The gate opened on exactly the
   case it exists to close.

   `list()` now takes br's `assignee` as the authoritative owner, ahead of the
   sidecar copy. Measured before/after on a real board: exit 1 (continue) →
   exit 2 (halt), naming the human holder.

2. A br-side refusal arriving between our read and our write — the genuine
   race, which no read-then-check can see because br evaluates it inside its
   own transaction — is now re-raised as ISSUE_ALREADY_CLAIMED instead of a
   generic command failure, so it too reaches exit 2 rather than exit 1.

3. The version floor was `if (this.brVersion && ...)`, so an unparseable
   `br --version` skipped the check entirely and let an unsupported binary
   through — failing open on the guard whose whole job is failing closed.

Also: `adev issues claim` printed a stack trace above the message an operator
needs, because adapter construction (br missing, br too old) throws and only
`issues stale` caught it. Now both report one actionable line.

Verified end-to-end against br 0.1.45 (kept as a rollback copy) and 0.2.22:
old-br entry points give a single line and exit 1; `coordination scan` already
degraded correctly with board-unavailable:BEADS_VERSION_UNSUPPORTED.
