## Intent

docs(hooks): document git hooks shipped by installer + session-file convention

Closes the documentation gap for the four git hooks that the installer
(npx @adev-org/adev-cli install) copies into every adopting project's
.githooks/ directory. Previously the post-commit hook auto-generated
tracked content (.context-index/sessions/<date>-<sha>.md per commit)
with no documentation telling adopters what the files are or how to
manage them.

Changes:

- docs/hooks.md: adds a new ## Git Hooks section after the Claude
  Code hook docs, documenting pre-commit, prepare-commit-msg,
  commit-msg, and post-commit. Covers the dual-surface concept
  (Claude Code hooks gate tool calls; git hooks gate or annotate
  commits) and the session-file batching convention with an explicit
  decision table (track + batch vs gitignore). Also clarifies the
  naming collision between .session-tracking.jsonl (gitignored,
  Claude Code session-capture hook) and .context-index/sessions/*.md
  (tracked, git post-commit hook).

- cli/index.mjs: adds a one-time installer notice after setupGitHooks()
  runs (both install and upgrade paths) explaining that sessions/ is
  tracked content and giving the batch-commit / gitignore choice with
  a pointer to docs/hooks.md. Adopters see this once at install time.

- skills/init/SKILL.md: adds a Session History Files section so
  /adev:init surfaces the convention when scaffolding context-index,
  including the gitignore opt-out path.

Discovered during verbosity-axis-and-output-trimming PR #143 work:
the PR branch accumulated ~30 untracked session files from cherry-
picks; investigation revealed the gap is adev-wide, not project-
specific. Filed as issue-518 (local task board).

Out of scope for this PR (deferred):
- Auto-gitignoring sessions/ in the installer.
- Auto-batching in the post-commit hook itself.
- A manifest.yaml sessions: tracked|gitignored config knob.
- A /adev:hygiene audit pass for untracked session files.
