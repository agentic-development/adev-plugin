## Intent

feat(reviewer-domain-fit): add falsification-gate action spec

Phase 1 of the reviewer-domain-fit initiative — the gate whose result decides
whether the evidence track proceeds. kind: action, since it is a one-shot
experiment producing a recorded verdict rather than changed behaviour; the
action template's postcondition-first framing fits (define DONE, then steps).

Six postconditions, six procedure steps, ten acceptance criteria.

Two things the charter left implicit and this spec pins down:

- The five ids (he2, r5sc, zx5, rftq, ysqd) are ISSUES, not specs. Step 1 must
  resolve each to a spec path plus a pre-fix commit, and an id with no governing
  spec is recorded UNMAPPED rather than substituted with a loosely related spec
  to preserve the denominator.
- The 3-of-5 bar assumes five map. If fewer do, the denominator becomes the
  number that mapped and the bar is ceil(0.6 x denominator) — fixed and written
  down BEFORE any run is scored, so the threshold cannot drift to fit the result.

Scoring requires two independent judgements per run: the defect was named by a
blocker-severity finding, AND the citation resolves at the reviewed commit. A
finding that names the right defect with an unresolvable citation counts as NOT
caught — which is the loadResumeParser failure mode the whole initiative exists
to address, so the experiment must not score it as a success.

Idempotency section records that Step 4 appends to append-only lifecycle logs, so
scoring must read the preserved .review.md copies rather than the projection,
which would blend runs. Rollback deliberately does NOT delete the finding: a
negative result is the experiment's product.

Bound to adev-plugin-j7pq.5.1.

Note: the partial_schema marker the skill requires at the head of the .partial
sits above the frontmatter, which adev/frontmatter-present rejects. Stripped on
the atomic-rename commit; the skill does not say to, and diagnose fails if you
do not.
