## Intent

fix(hooks): stop interpolating Spec: trailer into post-commit node block

The post-commit hook derived `specsTouched` from the commit message's
`Spec:` trailers and embedded that value directly in the source of its
`node --input-type=module -e` block:

    specsTouched: '${SPECS_TOUCHED}'.split(',').filter(Boolean),

Commit messages on a fetched branch are attacker-controlled, so a crafted
trailer executed arbitrary code on the machine of anyone who merged or
pulled it — while the hook printed nothing and exited 0. Sibling values
(COMMIT_SUBJECT, COMMIT_BODY) were already JSON-escaped through a stdin
round-trip; this one was not.

Pass the value through the environment as ADEV_SPECS_TOUCHED and read it
via process.env so it is never parsed as source. While in the parsing
path, also drop absolute and `..`-traversing entries and cap the list at
50, so a crafted trailer cannot inject paths that downstream consumers
would resolve.

Verified before the fix with an ESM payload (top-level await + dynamic
import): it wrote a marker file while the hook reported success. The new
regression test fails 4/4 against the pre-fix hook and passes 4/4 after.
The 26 existing session-capture tests still pass.

Note: the working tree also contained an unrelated 92-line truncation of
this hook that left it syntactically invalid (`sh -n` failed, so the hook
was not running at all). Restored from HEAD — the file's history is all
feature work and four open issues extend session capture, so nothing
indicated a deliberate retirement.
