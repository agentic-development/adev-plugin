## Intent

docs(charter): correct the xg1f.6 diagnosis and clear Phase D orphans

Charter review iteration 3 found my model of xg1f.6 was wrong in its central
claim, and two Phase D artifacts survived its removal.

The bug is a FILENAME SCHEME MISMATCH, not a root-visibility gap. Verified:

- spec-template and charter-template ARE in DOMAIN_CONFIG_FILENAMES
  (lib/domains/constants.mjs:23-31), mapped to KIND-LESS names, so
  loadDomainConfig already reads them project-local-first exactly like
  reviewers.yaml. The charter's claim that they are "never found" was false.
- resolveTemplate builds a KIND-SUFFIXED `${layer}-template.${kind}.md`
  (lib/template-resolution.mjs:221).
- `find templates/domains extensions -name "*-template.*.md"` returns ZERO.

So resolveTemplate's domain-override branch (Behavior 2) has never resolved for
any real domain, vendored or installed — only for synthetic test fixtures. The
charter's second claim, that the gap was "invisible only because extensions are
vendored plugin-side", was also false: the plugin-side path does not work either.

Operator decision: domain overrides go KIND-LESS. resolveTemplate's
domain-override step asks loadDomainConfig for the kind-less config type,
inheriting its project -> templates/domains/<domain>/ -> extends-parent
precedence. The kind-suffixed bundled fallback is untouched, so Behaviors 3 and
4 hold. A domain overrides per layer, not per kind.

Replaced "mirroring loadDomainConfig's precedence" — which had no unique
referent, since the two chains are not isomorphic — with the literal chain, plus
two consequences named explicitly: BUNDLED_OVERRIDE_BLOCKED must not propagate
out of template resolution, and skills/specify/SKILL.md:159's hardcoded plugin
path is replaced by the same loadDomainConfig call.

Three unfalsifiable ACs replaced with seven, covering: install-not-vendor
resolution for both Step 2 and Step 5, the precedence chain, the
BUNDLED_OVERRIDE_BLOCKED non-propagation, the mandatory
template-resolution.spec.md amendment (Behavior 2 + Preconditions + Behavior 8
containment roots), specify and brainstorm plus their four provider mirrors, and
preservation of the existing bundled fallback.

Phase D orphans cleared: the Out of Scope network-fetch sentence still said
software was "vendored and installed offline", and the extensions dependency row
still said "software becomes an extension". Both false since Phase D was cut.

Unbundling blocker count corrected to "six, of which this initiative removes
one; five remain" so xg1f.5 inherits an accurate figure.

xg1f.6 itself carries a correction comment recording the real diagnosis.
