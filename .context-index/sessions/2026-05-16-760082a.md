## Intent

feat(extensions): extension authoring docs bundle (issue-485)

Closes the post-cli-driver-surface documentation gap surfaced in
issue-485: extension authors had to spelunk across 6+ sources to
assemble the full `adev-extension.yaml` authoring path. After PR #116
shipped `adev report --type validator` as the universal write surface,
the substrate for extension-authored validation checks was in place
but the path was undocumented.

Ships three deliverables in one bundle:

  · extensions/example-validation-check/ — reference extension
    · adev-extension.yaml (16/25 lines) — canonical
      `provides.governance: [{target, entries[]}]` shape
    · bin/check.sh (6/15 lines) — hardened bash no-op:
      #!/usr/bin/env bash, set -euo pipefail, no env/argv/stdin reads,
      no eval/source/cmd-sub
    · README.md (47/60 lines) — install/verify/constraints/modify

  · templates/adev-extension.example.yaml (107 lines) — commented
    manifest template exercising all 5 provides.* slots

  · docs/extensions.md (191 lines) — author guide:
    · Schema for every provides.* slot
    · ADR-0003 install-time merge semantics
    · Validate-time event flow (check → `adev report --type validator`
      → write-time diagnostic hook)
    · Pitfalls section: missing profile (configurable-checks B13),
      string-form command (B6a), missing requires.adev, missing
      governance.id, profile-permissions threat model (SEC2-2),
      Untrusted Sources subsection (SEC2-9)
    · Worked example pointing at the reference extension

Tests (3000 total → 3028; +28 new):
  · tests/lib/extensions/example-validation-check-install.test.mjs (15)
    — manifest parse, template parse, bin hardening (4 sub-tests),
    install positive path, string-form rejection, collision report,
    absolute-path resolution, line-budget caps
  · tests/integration/extension-validate-flow.test.mjs (2) — install +
    `adev report --type validator` emission end-to-end
  · tests/docs/extensions-links.test.mjs (11) — doc-link sentinel
    asserting every code symbol in docs/extensions.md resolves

Lifecycle artifacts:
  · Charter rev 3 → 4 (Out-of-Scope amendment: documentation +

    are IN scope)
  · Spec extension-authoring-docs (rev 2) — review-passed → implemented

  · Charter Capability Map: row "Extension Authoring Documentation
    Bundle" → validated

    follow-up) closed
