## Intent

test(cli-driver-surface): e2e integration tests for CLI verb composition

Adds tests/integration/cli-lifecycle.test.mjs covering the seams BETWEEN
the cli-driver-surface verbs. Per-verb tests (tests/cli/*.test.mjs) cover
each verb in isolation; these tests cover chained sequences that mirror
the real /adev:specify → /adev:review-specs → /adev:plan → /adev:implement
→ /adev:validate flow.

The charter's elevator pitch is "make lifecycle events reliably emitted."
Shipping the CLI work without proving multiple verbs co-emit correctly
would be a credibility gap. These tests close it.

Scenarios (all run against a temp-dir project with a real git repo and
the actual `node cli/index.mjs` binary — no mocks at the verb boundary):

1. Happy path full lifecycle
   - Walks specify → review → plan → implement → validate
   - Each step: reportStep started → reportStep completed (with verdict)
   - Each transition gated by `adev gate require --skill <next>`
   - Plan emits plan_task pending; implement transitions pending →
     in_progress → done
   - Validate emits a validator_report
   - Asserts:
     · lifecycle_step events appear in STEP_ORDER
     · step_completed events all PASS in STEP_ORDER
     · plan_task transitions pending → in_progress → done
     · validator_report carries the right validator id + verdict
     · `adev state current` projection shows all 5 steps completed PASS

2. Gate violation
   - Skips implement after plan completes
   - `adev gate require --skill validate` exits 2 with GATE_BLOCKED
   - The failed gate emits NO lifecycle event (gates are read-only)
   - Confirms strict-mode default ordering enforcement

3. Drift detection
   - Stamps a spec source-manifest with a tracked file's sha
   - `adev source-manifest verify` reports PASS pre-drift
   - Modifies the file, re-runs verify
   - Asserts WARN output naming both the expected sha and the drifted file
   - Confirms non-blocking drift contract (exit 0 + WARN per Check 1.5)
