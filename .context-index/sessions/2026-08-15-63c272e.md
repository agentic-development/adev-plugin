## Intent

docs(governance): hardening spec rev 3 — derive the tables from code, exclude gates.yaml

Rev 2 closed all 12 rev-1 blockers and drew 11 new ones. The reviewers named
the cause precisely: four closures were assertions rather than mechanisms, and
the two tables rev 2 introduced carried rows contradicting the schemas their
consumers enforce. I had been writing normative content from memory and
letting review find the errors. This revision derives it from the code first.

That turned one blocker into a design decision. Rev 2 excluded `command` from
the gates allowlist to close the injection path — but merge-gates.mjs:29-33
makes `command` a *required* field and discards any gate lacking it, so rev 2's
fix would have silently thrown away every extension-contributed gate. Closing
an injection path by breaking the feature is not a fix. Since there is no valid
extension gate without a shell string, and no safe subset of a shell string,
gates.yaml is now not extension-writable at all. Extensions that need to
execute contribute a diagnostics runner, which is what ADR-0010 assigns that
surface. Four writable registries, not five.

Invariant 6 was simply false and is restated rather than patched. A
diagnostics `runner` IS executable — import()-ed and invoked. What bounds it is
the containment guard already shipped in lib/diagnostics/index.mjs: `..`
rejection before resolution, prefix-scoped roots, realpath check. That guard is
now named as a dependency of the invariant instead of being silently assumed.

Invariant 2 was false too. lib/profiles/yaml.mjs parses `{ … }` as a flow map,
so a scalar of `{command: rm -rf /}` reparses into a map with attacker-chosen
keys; the rejection set omitted flow indicators entirely. It also coerces bare
integers to Number, so a numeric id would bypass the string-keyed collision
check. Both are now explicit behaviors.

Allowlists rebuilt per consumer schema, including `package` (ADR-0003's
two-stage reviewer form) and `enabled`/`disabled_reason`, which the parent spec
adds and which the old rows would have rejected. MERGE_WOULD_TRUNCATE dropped —
under the splice it has no reachable trigger and would have been dead. The
splice is now specified against all three layouts present on disk rather than
only validate.yaml's.
