## Intent

feat(work): pre-flight concurrency scan for /adev:work Step 1

Closes issue-606. Step 1 scanned four purely local signals — execution state,
plan-task projection, lifecycle states, recent sessions — and was blind to
every concurrent workstream. Two agents fixed the same p0 bug an hour apart
(PRs #214/#215), and a whole epic (epic-102, issues 568-581, PRs #210-#214)
stayed invisible to a study pursuing the same goal.

`adev coordination scan [--json] [--owner] [--limit] [--branch-age-days]`
gathers open PRs, remote branches, and in_progress issues held elsewhere.
Logic lives in the verb, not skill prose, per the cli-driver-surface charter;
Step 1 gains one numbered signal that names it.

Exit 0 whenever the scan completes, INCLUDING a fully degraded scan; 1 only
on usage error; never 2. A finding must not read as a failure at the top of
every /adev:work.

Degradation is explicit rather than silent. Each bucket carries
available:false plus a reason — gh-not-installed, gh-unavailable
(unauthenticated / no GitHub remote / rate-limited), gh-output-unparseable,
board-unavailable:<code>, and the git equivalents. A degraded bucket renders
as "? open PRs", never "0", and an all-degraded scan says "not scanned — no
signal available". Reporting "no concurrent work" when the truth is "could
not look" would rebuild the exact blindness this closes.

gh gets an 8s timeout against git's 3s: gh pr list measures 1.1-1.5s warm,
and a 3s budget would report "no open PRs" during a cold auth refresh.

Owner identity follows --owner then $ADEV_ISSUE_OWNER, mirroring resolveOwner
in issues-claim.mjs — deliberately NOT the ${USER}/${MODE} commit-trailer
scheme, which never reaches the board's owner field and would false-positive
on every claimed issue. Unset identity reports every claimed issue: a
duplicate-work detector should over-report. Unowned in_progress issues get
their own bucket, since issue-582 — the case that caused this — was unclaimed.
