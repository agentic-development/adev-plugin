## Intent

fix(cli-driver-surface): specify and implement emit verdict on step completion

Resolves issue-508 (under epic-74 / adev-compiler-discipline milestone).

/adev:specify and /adev:implement previously emitted
`adev report --type step --status completed` without `--verdict`, leaving
the lifecycle log entry with `verdict: null`. Downstream gates
(`adev gate require --skill <next>`) require the prior step to be
completed with a PASS or PASS_WITH_NOTES verdict, so both gates blocked
on the next skill invocation until an operator manually re-emitted the
completion event with `--verdict PASS`.

Three other lifecycle skills (review-specs, plan, validate) already
emit a verdict on completion. This commit brings specify and implement
into line with that contract.

Both completion-emission lines reach this point only on the success path
(specify: after spec is written and status set to review-pending;
implement: after the GREEN phase fires in Step 4). Failure paths emit
`status: failed` separately and are unaffected by this fix.

No code changes — markdown-only updates to two SKILL.md files.

Auto-stamped drift_detected on 21 specs whose source-manifest covers
skills/specify/SKILL.md or skills/implement/SKILL.md is correct hook
behavior; included.

Verified twice during the 2026-05-17 lifecycle run on
tree-sitter-repomap/non-code-reference-detection: review-specs blocked
after specify, validate blocked after implement, both unblocked by
manually re-emitting with --verdict PASS. This fix removes the manual
step.
