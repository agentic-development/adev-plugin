## Intent

docs(adr): ADR-0019 — built-in check registry + alias table for historical IDs

Amends ADR-0010 by naming where its validate.yaml row's phrase "New
built-in checks added to the skill itself" is declared machine-readably.
The six surface roles are unchanged.

Unblocks issue-562, which was stuck on a blocker (SA-9) with no legal
escape. Measured: skills/validate/SKILL.md emits 8 check IDs while
governance/validate.yaml registers 6, missing
validate.check-1-quality-gates and validate.check-1.6-code-drift. The
issue proposed making validate.yaml the closed enum, which would reject
exactly those two and stop recording Check 1 — the only check in the
live set that ever fails (23 PASS / 12 PWN / 11 FAIL). Adding them to
validate.yaml is closed off by ADR-0010's own text: "The skill is the
surface that runs the checks; it is not a registry for additional ones."

The real gap: ADR-0010 assigns built-ins to the skill but never says
where the skill's set is declared in a form a program can read.
SKILL.md is prose; BUNDLED_DETERMINISTIC_IDS is partial and claims no
authority. So the enum had no source.

Part A — lib/governance/check-ids.mjs becomes the authoritative built-in
registry in canonical qualified form. Legal emit set = registry ∪
project-declared IDs in validate.yaml, which keeps exactly the override
role ADR-0010 gives it and gains no new authority.

Part B — an alias table with a deliberate read/emit asymmetry: reading
never hard-fails (or replay over the historical corpus breaks, and that
corpus is the only record of what the gates did), emitting is strict (or
the vocabulary drifts again the moment it is cleaned up). Three classes:
canonical, alias, retired.

The table is data-derived from a census of the live corpus: 46 distinct
validator spellings, four families — prefix, separator (check-1-5 for
the decimal point), abbreviation (check-8-boundary for -boundaries), and
renumber (check-13-heuristic-extraction ->
validate.check-12-heuristic-extraction). The renumber family is why the
table must be hand-built: no normalising regex recovers a changed check
NUMBER.

Alternatives rejected in the ADR: validate.yaml as sole registry
(contradicts ADR-0010, blinds Check 1); union with no new module (three
sources, no owner); warn-only (seriously considered — warnings on a path
nobody reads are how the corpus reached 46 spellings); rewriting the
event log to normalise history (destroys the append-only audit property).
