## Intent

fix(build): record an implement BLOCKED halt without a step_failed event

The BEH-15 live run of the escalated-lite case in build mode halted
correctly inside implement (plan_task blocked with LOOP_BUDGET_EXHAUSTED,
no later task, STEP_RESULT BLOCKED), but the build orchestrator then ran
`adev report --type step --step implement --status failed` itself: Step 4
had branches only for gate failures and success, and nothing said that
implement owns its own step events. BEH-15 requires no step_failed for this
halt. Step 4 now says the orchestrator never emits implement step events,
and adds a BLOCKED branch that records build state only (failed, verdict
BLOCKED, so --resume re-enters at implement) and stops without waiting.
