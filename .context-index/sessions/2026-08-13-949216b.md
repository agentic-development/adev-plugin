## Intent

fix(issues): preserve source ids across migration — closes issue-628

A json -> beads migration gave every item a brand-new identity. Two
places conspired: lib/cli/issues-migrate.mjs stripped `id` in
projectIssueForCreate/projectEpicForCreate, and BeadsAdapter.create/
createEpic then overwrote `issue.id` unconditionally with _nextId().

Measured on this repo's real 310-issue board before the fix:

  - source issue-625 arrived as issue-fenorl
  - 0 of 41 dependency edges replayed, since the verb resolves edge
    endpoints by SOURCE id and nothing matched
  - every human-readable cross-reference broke, silently and unreported:
    board notes, commit messages, PR bodies and specs refer to issues by
    id ("tracked as issue-623"), and all of those would resolve to a
    DIFFERENT issue afterwards

The last point is the dangerous one -- the board would look complete and
internally consistent while meaning something else entirely.

Minting itself is correct for NEW work: issue-613 made ids merge-safe so
two branches cannot collide. It is wrong for a MIGRATION, whose whole
job is to carry identity across. The rule is now: honour an explicitly
supplied id, mint only when none is given. br enforces uniqueness on
external_ref, so a genuinely colliding supplied id fails loudly at
create rather than silently double-minting.

`dependencies` stays stripped (replayed in a second pass once every
endpoint exists); `created`/`updated` stay stripped so the target stamps
its own.

One pre-existing assertion asserted `passed.id === undefined` with the
rationale "source id must NOT be passed (adapter assigns)". UPDATED, not
weakened: that assertion codified the defect. Reasoning recorded inline.

Verified end-to-end against a real br 0.2.22 binary on the live
310-issue board: 310/310 numeric issue-N and 106/106 epic-N ids
preserved, ZERO random-minted, 44 dependency edges replayed (up from 0)
with no warnings. Spot-checked issue-625, issue-628 and epic-108 all
resolve; issue-108 is correctly absent (the source id range is sparse).

7 new tests. npm test: 5767 tests, 5765 pass, 0 fail, 2 pre-existing todo.
