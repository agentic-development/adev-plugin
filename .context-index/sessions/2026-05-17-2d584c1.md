test(agent-reliable-state-artifacts): CAS coverage + lock-file fix for true atomic CAS

Plan tasks 5-9:
- Task 5: legacy-document test — pre-CAS tasks.json without seq upgrades
  transparently on first mutation (stamps seq:1, no adev migrate needed)
- Task 6: expanded hostile-seed test — 5 invalid-seq cases (negative,

- Task 7: stale-write exhaustion test — STALE_BOARD_WRITE thrown after
  MAX_CAS_RETRIES exhausted; verifies error message contains op name +
  retry count only (no filesystem paths, no document contents)
- Task 8: N=10 concurrent mutators proof — spawns child processes via
  node:child_process; asserts every committed mutation lands on board,
  no silent loss, no orphan .tmp files; final seq equals committed count
- Task 9: internal-encapsulation grep test — flags any production JsonAdapter
  consumer (lib/, cli/, hooks/, viz/, providers/) that calls ._read or
  ._write directly. Narrowed to files that import json-adapter.mjs so
  FileAdapter's same-named methods are correctly excluded.

ROBUSTNESS FIX in _write: the original implementation re-read disk seq
immediately before renameSync but left a TOCTOU window — two writers
could both pass CAS at the same expectedSeq and both rename, losing one.
Task 8's concurrency test caught this directly. Fixed by acquiring an
exclusive lock via O_EXCL on a sidecar lock file (.lock) before the CAS
re-read; the lock serializes writers at the filesystem level so the
CAS check is now atomic with the rename. Lock-contention failures
surface as STALE_BOARD_WRITE_RETRY (consumed by the retry wrapper),
matching the existing stale-seq retry path.

This strengthens Behavior 8's contractual guarantee from "no silent
loss" to also covering the previously-acknowledged POSIX TOCTOU window
(spec SA-3). Spec wording does not need revision — the implementation
now meets the stronger guarantee the test asserts.
