## Intent

feat(spec-lifecycle): compute addressed/unresolved from a real per-anchor text diff

Replaces reviseSpec's hardcoded blanket-acknowledgement (addressed=all
input, unresolved=[]) with real per-anchor splicing: resolveSectionAnchors
maps headings to content byte ranges, authored bodies are validated per
BEH-5a (refuse frontmatter-fence lines and control characters,
independently per anchor -- one refusal never aborts a sibling's valid
splice), and a final whole-document reparse gates atomicity per BEH-5
(never partially applied -- on gate failure every implicated anchor
rolls back to unresolved, nothing is written).

Fix (review cycle 2): the atomicity gate originally censused every
`---`-only line across the whole document, which false-rolled-back
specs with legitimate pre-existing horizontal rules in the body
(several exist in this repo already). Narrowed to a tolerant
whole-document reparse confirming the frontmatter block still parses
with the expected revision/status fields -- splices are structurally
bounded to content after the closing fence, so they cannot corrupt
the frontmatter block itself.

Also exports groupBlockersByAnchor (Task 7 depends on it) and
parseBlockersSidecar.

Known, plan-sequenced gap: tests/integration/build-loop-auto-retry.test.mjs
now fails -- it asserts the pre-fix blanket-acknowledgement behavior.
Task 9 (join task, depends on this) extends that file with real
authoredSections wiring; until then this is expected transitional
breakage, not a Task 6 defect.
