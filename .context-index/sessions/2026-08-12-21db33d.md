pr-body-advisories — the grammar is deleted, not patched.

Revision 1 authored its own ## Parallelization grammar and claimed it was
"verified against real shapes". It was checked against two plan files. The
reviewer measured all 138 and found a third fell through every rung into a
silent empty reading order — the exact failure the ladder existed to
prevent. Rather than widen my grammar, the spec now consumes
parseParallelizationSection from lib/parallel/groups.mjs, which
worktree-parallelization already owns and /adev:implement --parallel
already uses. One on-disk format, one parser; the two-grammars divergence
had no owner and no test that would have caught it drifting.

Consuming it inherits a defect worth naming rather than papering over:
"Tasks 14, 15, 16, 17" matches the group regex but yields members: [] with
malformed: false, so the parser reports success for a group with no tasks.
Verified by probe. A zero-member group therefore drops its plan to a
degraded rung. Rung 4 is new, for the 48 of 138 plans with no ## Task
Summary — rungs 2 and 3 previously sent them to a table a third of the
corpus lacks. Coverage is stated as measured (79 usable / 59 malformed,
~57%), which is lower than revision 1 claimed for itself, with an
acceptance criterion that recomputes the figure so it cannot rot.

Widening the shared parser's qualifier would lift that to ~101/138 and is
tempting, but it would move those plans from serial fallback into
concurrent execution in another charter's module without evidence the
groups are independent. Deferred with the numbers recorded.

pr-body-composition — two input contracts and one encoder.

Verification no longer parses .validate.md. skills/validate/SKILL.md:405
says outright not to, and ADR-0012 makes .md human-primary narrative; the
spec now reads state.steps.validate from the lifecycle projection with a
typed field table, at the spec's current revision, and renders a verdict
recorded against an older revision as explicitly stale rather than current.

The task universe is now the (spec_path, task_id) set from Plan-task:
trailers, with file sets from git diff-tree. Revision 2 said a task
"appears in the changed files", presupposing a mapping routing.json does
not carry — UNKNOWN was unimplementable and untestable. It is now a set
difference between git and the sidecar.

SEC-1/2/3 collapse into one Output Encoding Contract applied at a single
interpolation boundary: path containment for trailer-derived paths (CWE-22),
table-cell safety including the pipe and applied to rationale (CWE-116),
marker-literal neutralization, and diagnostics to stderr with repo-relative
paths. Marker neutralization matters most — the authorship boundary rests
entirely on those two literals appearing nowhere else, so a crafted
rationale could otherwise forge the closing marker.

Warnings fixed in the same pass rather than deferred to another BLOCK
round: scores.blast_radius nesting and descending sort, marker-assembly
ownership, empty-range renders all five slots, manifest demoted to
optional, --head argument added so determinism has a nameable pair, and the
