## Intent

fix(implement): resolve test depth for every task, not only before write-test

`adev test-policy resolve` ran only "before dispatching the write-test
subagent", but the per-task loop never dispatches one: the implementer
writes its own RED tests under the TDD mandate. Resolution therefore
never ran. A consumer project recorded 0 test_depth_assigned events
across 136 tasks, so the risk-level and sensitive-path floors never
reached the agent writing tests. The spec's ownership section rested on
the same misreading (it cited the line describing how to configure
write-test *when* dispatched as evidence that it is dispatched).

- Step 2c resolves depth for every task before composing the implementer
  prompt and passes it as a `## Test Depth` section (with floor_legs).
  A write-test subagent, when dispatched, gets the same value; never
  resolve twice.
- assert-assigned runs after the implementer reports (or a write-test
  suite is accepted); MISSING_DEPTH_ASSIGNMENT blocks Stage 1 review.
- tdd-mandate.md tells the implementer which case classes each depth
  requires.
- The Step 2 body summary no longer claims a write-test dispatch.
- test-depth-policy spec rev 8 corrects Ownership and Behavior 14; the
  implementation-mode charter and docs/test-strategies.md follow.
