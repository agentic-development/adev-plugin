## Intent

fix(issues): make the beads backend work against br 0.2.x, with claim parity

The beads adapter was written against br 0.1.x and was completely
non-functional against current br. Every call died on
"Database error: I/O error: Is a directory (os error 21)" because `--db` was
handed `.beads/` — the workspace DIRECTORY — while br wants the database FILE
inside it. Nothing caught this: the existing tests mock br or construct the
adapter with checkBr:false, so they asserted our argv and never that a single
command succeeds.

Found by driving a real br 0.2.22 binary. Four defects, in the order they hid
behind each other:

1. `--db` now resolves the *.db file inside .beads/ (preferring beads.db),
   and omits the flag entirely when the workspace is uninitialized so br
   applies its own auto-discovery and its own clearer error.
2. That path is canonicalized: br refuses a route with a symlinked parent
   ("Refusing configured database route with a symlinked parent"), and on
   macOS /var -> /private/var is enough to break every call. This is the same
   realpath lesson the execution-state resolver hit two commits ago.
3. _runBr now surfaces stdout when stderr is empty. br reports structured
   failures as JSON on STDOUT, so a stderr-only message degraded to a bare
   "Command failed: <argv>" — which is why (2) took a manual repro to find.
4. Epics were delegated to FileAdapter, which is read-only-deprecated, so
   createEpic threw BACKEND_READ_ONLY_DEPRECATED. Since /adev:implement
   creates an epic as its FIRST board action, the lifecycle was unusable on
   beads regardless of the above. Repointed at JsonAdapter, constructed
   lazily because JsonAdapter validates its root eagerly while BeadsAdapter is
   legitimately built against paths that do not exist (the migrate probe).

claim/release now exist on beads. br 0.2.x supplies the primitive natively:
`update --claim` sets assignee=actor + status=in_progress and refuses a held
issue inside br's own transaction, so two racing agents cannot both win. adev's
`owner` maps onto `assignee` because assignee is the field --claim guards.
Preconditions reuse requireClaimable/requireReleasable, so refusal codes and
CLI exit codes are identical across backends and callers never branch.

KNOWN NON-PARITY, documented rather than papered over: stale-lease takeover is
NOT atomic on beads. br will not reassign a held issue, so expiring a lease
takes two calls. Two agents observing the same expired lease can both proceed.
Bounded by TTL expiry rather than contention, so far narrower than the
no-gate-at-all state this replaces — but json remains the backend with an
atomic takeover. Full matrix in docs/cli-reference.md.

A version floor (>= 0.2.0, BEADS_VERSION_UNSUPPORTED) replaces the bare
`which br`, so a 0.1.x user gets one actionable message instead of the
obscure failure above.

Live coverage lands in tests/evals/beads-live/ — the opt-in bucket, per the
issue-612 decision — and FAILS LOUDLY when br is absent rather than skipping,
so a green default run never implies a verified beads backend. It drives a real
binary deliberately: the guarantee under test is br's, and a mocked br would
assert our argv while proving nothing about exclusivity.

Two test expectations changed, both because the behavior genuinely changed:
json -> beads migration now reports the epic as already_migrated, since beads
epics live in tasks.json and are therefore already at their destination. The
old expectation of 0 was never reachable — a real (non-dry) run of that
migration threw on the read-only FileAdapter.
