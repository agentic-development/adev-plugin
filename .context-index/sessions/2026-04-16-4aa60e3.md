## Intent

feat(task-management): unified create() and close() API (issue-78)

Implements unified-create-api spec — collapses createTiered/closeTiered
into the canonical create()/close() with internal tier-aware branching.

- create() now infers tier prefix from parent_id depth + 1; root items
  use defaultRootPrefix ("e"). Explicit tier_prefix overrides inference.
  Throws MAX_DEPTH_EXCEEDED when parent is at max tier depth defined
  by TierConfig (no auto-fallback). Legacy flat-ID path preserved when
  no parent_id and no tier_prefix.

- close() checks parseId() — tiered IDs apply cascade guard before
  dependency guard; legacy flat IDs skip cascade entirely. Subsumes
  closeTiered (kept as thin delegate for back-compat).

- spec_ref: distinct new optional field on Issue typedef and tasks.md
  table (between Plan-Task and Deps in 14-column format). Separate
  from plan_ref — both can be present. Beads adapter persists via
  metadata sidecar.

- createEpic/updateEpic continue to delegate to create()/update().
  Emit one-time console.warn when ADEV_DEPRECATION_WARN=1.

- Backward-compat row parsing: file adapter handles 12-col (legacy),
  13-col (next_action only), and 14-col (spec_ref + next_action).

Tests added (32 new): tests/issues/unified-create.test.mjs covering
tier inference, MAX_DEPTH_EXCEEDED, spec_ref round-trip, deprecation
warning gating, unified close cascade behavior, legacy ID compat.

npm test: 938/938 passing.
