## Intent

fix(build): Step 0 specify-skip reads lifecycle log instead of dispatching --revise

Closes issue-527.

Before: skills/build/SKILL.md Step 0 said "Spec file EXISTS but no current
passing .review.md: dispatch /adev:specify --spec <path> --revise". But
/adev:specify does NOT carry a --revise flag — its workflow axis is
{extract, refactor, from-diff, cross-cutting}, no revise. Standard mode
fall-through would re-author over the existing spec without overwrite
guards. The broken contract was codified in the adev-build-skill spec
(Behaviors 8a, AC 276), so a SKILL-only patch would be reverted by
spec-drift detection.

Fix: replace the broken dispatch with three lifecycle-aware skip
conditions on Step 0:
  1. .review.md exists with PASS verdict (preserved)
  2. lifecycle log shows specify completed with PASS or PASS_WITH_NOTES
  3. spec file exists on disk (review will catch any drift)

Dispatch path is now: only when no spec exists AND no specify event in
the lifecycle log — pure creation mode, no --revise.

Updates the spec at adev-build-skill.spec.md Behavior 8a, pseudo-pipeline
diagram (line 118-121), and AC 276 to match.

Infrastructure already in place — currentState() exposes state.steps.specify
and the orchestrator already imports it. No new code required.

Out of scope (separate followup): skills/build/SKILL.md line 367 — the
blocker-fix loop also dispatches /adev:specify --revise --blocker-context.
Same family of bug, different code path. File as a new issue.
