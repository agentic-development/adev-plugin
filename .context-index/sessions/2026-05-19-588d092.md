## Intent

fix(githooks): prepare-commit-msg appends trailers in same paragraph

Closes issue-526.

Before: `printf '\n%s' "$TRAILERS"` unconditionally inserted a blank line
between the existing in-body trailer block (from a HEREDOC commit message
ending with Spec:/Plan-task:) and the appended trailers (Author-type:/
Operator:/Issue:). Git's trailer convention parses only the LAST paragraph
of the message — so `git log --format=%(trailers)` returned Author-type/
Operator/Issue but silently dropped Spec:/Plan-task:. Downstream consumers
(/adev:retro Pass 14, /adev:hygiene Pass 14) read these as untraced files.
Impact: every adev commit since the hook landed in 1b03ed8 (2026-04-12),
including 38/38 cursor-provider commits in this branch.

Fix: inspect the last non-empty line of the message. If it already matches
the trailer-format regex `^[A-Za-z][A-Za-z0-9_-]*: `, append without the
leading newline (single contiguous trailer block). Otherwise, keep the
prior new-paragraph behavior.

Regression coverage at tests/githooks/prepare-commit-msg.test.mjs uses
`git interpret-trailers --parse` to assert every injected trailer appears
in the canonical trailer block — 3/3 cases pass (in-body block, fresh
paragraph, mixed seed).

Spec acceptance criterion added at structured-commit-trailers.spec.md:78
to lock the invariant going forward.

Note: 38 already-stranded commits on this branch retain the split block;
that backfill is out of scope (history rewrite is high-cost). Downstream
passes will need a body-fallback parser or a one-time exempt-commits list.
