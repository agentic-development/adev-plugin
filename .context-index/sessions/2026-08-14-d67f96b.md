## Intent

docs(governance): make extension check contribution conform, and fix its blockers

Extensions already use the target model — provides.governance is merged into
the project's own yaml at install time, project-wins on collision, with no
runtime overlay. Single-source is the model extensions already follow; the
bundled and domain defaults are being brought into line with them.

The implementation is destructive, though, and this spec cannot land without
fixing it. Verified by running the reference extension's own entry against a
real validate.yaml holding 7 checks: the file came back as three lines under
`validators:` with all seven checks gone. Two compounding defects —
inferRootKey maps validate.yaml to `validators` while the schema key is
`checks`, and serializeGovernanceYaml emits one root key with no sibling or
comment preservation. The second would erase the `transitions:` block this
spec populates, so the fix is sequenced ahead of any step that writes to a
governance file.

Also closes three gaps the merge never had: provenance (a source: field, so
uninstall and the widened drift pass can tell extension entries from
project-authored ones), governance reversal on uninstall, and an explicit
registry-to-root-key table rather than stem inference that happens to work
for boundaries and diagnostics by luck.
