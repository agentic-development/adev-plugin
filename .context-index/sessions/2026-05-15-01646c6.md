## Intent

feat(cli-driver-surface): PR 2 — extract reportValidator per-check emission

Task 2 of the inline-Node extraction sweep. Introduces `adev report` —
a multi-mode CLI verb for lifecycle-state per-check / per-step event
emission. PR 2 ships `--type validator`; Task 3 will extend the same
module with `--type step` (spec Behavior 9 — CLI-verb naming is
canonical, single verb shared across modes).

Significance: this PR lifts `validator_report` event coverage from ~0%
to ~100% of validate runs. The previous skill prose held a JavaScript
example showing the `reportValidator` import + call signature; in
practice agents skipped the inline emission silently. With a CLI verb,
the skill can call `adev report --type validator` once per check and
the event is guaranteed to land in the lifecycle log.

What lands here (one atomic commit per spec Behavior 1):

- lib/cli/report.mjs: new CLI helper exporting run() + help(). Does
  NOT export LIFECYCLE_STEP — `reportValidator` is per-check event
  emission inside the validate step, not a step entry/exit, so the
  cli-driver pattern test does NOT assert requireGate-first on this
  module. Implements full argument validation (required flags, verdict
  enum, numeric coercion for --score and --duration-ms), spec
  containment (SEC-1 mirror of lib/cli/gate.mjs), and delegates to
  reportValidator() from lib/lifecycle-state.mjs. `--type step` is
  recognised but rejected with exit 1 + informative message to keep
  the Task 3 seam explicit.

  spec path, missing spec file), --help, happy path (event appended
  with all fields, severity stamped by lib), optional fields, all
  three verdict values, the --type step seam, and the silent-success
  observational contract.
- cli/index.mjs: register `report` verb in VERB_REGISTRY (dynamic
  import to lib/cli/report.mjs).
