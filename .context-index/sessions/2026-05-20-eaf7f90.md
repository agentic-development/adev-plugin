## Intent

feat(plan-routing-sidecar): switch from markdown to JSON before ship

Pre-ship correction: the routing sidecar is relational/structured data
(per-task scores across 4 numeric dimensions plus categorical fields),
not narrative. Markdown-with-fenced-YAML required two parses
(markdown → YAML); native JSON is one. Aligns the routing peer with
the charter's "JSON for relational state" principle that already drove
tasks.md → tasks.json.

Lib + CLI:
- lib/plan-routing-sidecar.mjs: rewritten to emit
  { version: 1, _generated_by, entries[] } via JSON.stringify; reader
  validates schema version and surfaces new INVALID_SIDECAR_JSON error
  code on malformed / version-mismatched payloads. New
  renderRoutingMarkdown() helper exposes the human view.
- lib/cli/route.mjs: emit-sidecar writes <stem>.routing.json; new
  render-sidecar subverb prints the markdown view to stdout for humans
  who would otherwise need jq.
- lib/cli/implement.mjs: surfaces INVALID_SIDECAR_JSON cleanly.
- lib/plan-immutability.mjs: detector now checks for the sibling
  <stem>.routing.json (the PLAN_MUTATED_WITHOUT_SIDECAR check).

Skills + tests + fixtures:
- skills/route/SKILL.md, skills/implement/SKILL.md: .routing.md →
  .routing.json; route SKILL points humans at render-sidecar.
- tests/lib/plan-routing-sidecar.test.mjs: JSON-shape assertions
  + new INVALID_SIDECAR_JSON coverage (malformed JSON, wrong schema
  version, non-array entries) + renderRoutingMarkdown coverage.
- tests/cli/route-emit-sidecar.test.mjs: assertions check JSON output
  + new render-sidecar happy-path and missing-sidecar tests.
- tests/cli/implement-read-routing.test.mjs: adds INVALID_SIDECAR_JSON
  case.
- tests/skills/route.test.mjs, tests/specs/plan-task-events-con8.test.mjs:
  expect .routing.json.
- Three plan-immutability fixture plan-body comments updated; the
  seed sidecar renamed from .routing.md to .routing.json with JSON
  content.
