## Intent

docs(copilot-provider): explain opts.projectRoot+user divergence from peer adapters

The Copilot adapter's install/uninstall/status surface takes
{ projectRoot, dryRun?, user?, force? } rather than the
{ scope: 'user' | 'project' } shape used by Claude Code / OpenCode /
Codex. The README anchors the rationale: peer adapters are user-scoped by
design (their plugin homes live outside any consuming project), while
Copilot is repo-scoped by design (.github/ lives in the consuming
project). Future adapter authors should pick the convention that fits
their substrate, not enforce uniformity for its own sake.
