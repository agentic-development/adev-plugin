## Intent

docs(governance): hardening spec rev 2 — close all 12 rev-1 blockers

Rev 1 drew 12 blockers, all three reviewers converging on one class: behavior
specified against mechanisms that neither exist nor appear in the Changes
Catalog. Two could not be closed by editing this spec at all.

Cross-spec first. explicit-governance-registries still claimed four of the
same edits — inferRootKey, serializeGovernanceYaml, the test fixup, and the
uninstall verb — so a revise loop scoped here would have reported those
blockers persistent forever. The parent is pruned; `source:` is now declared
here (installer-stamped) and the parent extends its vocabulary, which keeps
the dependency one-way.

Uninstall reversal is dropped, on review advice. No uninstall path exists to
add reversal to — `adev extension` has only install and list, and no
uninstallExtension exists in lib/ at all. Filed as adev-plugin-xg1f.3 with
the `source` field named as its prerequisite.

The command-injection claim was wrong and is now actually true. Append-only
closes the collision half; a newly appended gates.yaml entry still reaches
spawnSync. The fix is the allowlist, not the merge strategy: `command` is
absent from every registry's allowed fields, so no install path can introduce
an executable body. An extension needing to execute ships a diagnostics
runner, which runs as a module rather than a shell string.

Escaping becomes rejection. lib/profiles/yaml.mjs::unquote strips quotes and
performs no unescape, so no backslash scheme round-trips through the repo's
own parser, and a YAML dependency would need an ADR. Unsafe scalars are
refused with GOVERNANCE_SCALAR_UNSAFE instead — governance config has no
legitimate multi-line value.

Comment preservation likewise stops depending on a serializer that does not
exist: the write is an in-place line splice, so comments survive by never
being parsed.

Also enumerated the two tables that were the central ADDED artifacts and were
never written down — the writable registry-to-root-key table (five of seven
files; risk-policies.yaml and sensitive-paths.yaml explicitly non-writable,
being the project's own guard boundary) and the per-registry field allowlists.
And replaced the catch{start fresh} parse fallback, which silently destroys a
registry and bypasses collision detection.
