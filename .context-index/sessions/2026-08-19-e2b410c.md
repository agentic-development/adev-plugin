## Intent

docs(skills): make the SKILL.md size limits an authoring-time constraint

Both limits previously existed only as a constant inside a Copilot
provider module, so an author editing a SKILL.md got no signal until CI
failed four call frames deep in buildPlan() with an error naming a file
their change was not about (adev-plugin-skill-size-headroom-wnn9, item 3).

  - constitution.md / CLAUDE.md: both limits, why prose deletion is the
    wrong fix for either, and what stays in the body regardless of size
  - docs/skill-reference.md: how a skill is laid out on disk, what the
    body vs references/ split is for, and the conditional-loading pattern
  - tests/skills/skill-size-cap.test.mjs: a guard for the ~5,000-token
    guidance alongside the existing hard-cap assertion

The new guard estimates tokens from bytes. That is honest for a budget --
a consistent ruler over a fixed corpus -- and the comment says explicitly
that it must not be reused to claim token savings, where the stored module
heuristic warns byte proxies overstate by 2-2.5x.
