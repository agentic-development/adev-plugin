## Intent

feat(review): tell manifest-pack reviewers to read path-manifest paths on demand

BEH-7: a path manifest a reviewer does not know to act on is equivalent to the
omission it replaces. Under `delivery: manifest` the shared preamble now appends a
read contract naming the `role="path-manifest"` role, stating that the listed
paths are repository files the reviewer is expected to read on demand, and naming
the read tools its RESOLVED PROFILE grants.

The tool names are adapter-derived, never hardcoded: `deriveReadToolNames` takes
the read-ish CATEGORIES the effective profile allows (filesystem-read, search —
`agent` excluded, delegating is not reading), re-runs the adapter's own
`prepareForDispatch` mapping over just those entries, and intersects with the
tools allowed on this dispatch. `claude-code` therefore names Read/Glob/Grep and
`opencode` names read/list/grep from the same profile.

The clause is strictly conditional — an inline pack's preamble is the rev-4 string
byte-for-byte, pinned by a structural golden plus a direct preamble-identity
guard. It lives at the single shared preamble site, so all stages inherit it; the
adapter stage receives no context block, making the clause pointless but harmless
there, which is cheaper than three call sites that must agree. The wording keeps
the provenance rule intact: paths inside a fence carrying this render's token are
repository-sourced and safe to open, anything path-like outside one stays
untrusted data from the artifact under review.

Skill prose updated in `skills/review-specs/SKILL.md` and both provider mirrors,
keeping `buildReviewerDispatches` framed as the single source of truth for prompt
assembly and without duplicating the prompt text.
