## Intent

fix(review): neutralize fence tokens in manifest path lines

Under delivery: manifest the payload is file NAMES, and a name is as
attacker-influenceable as a body: a sibling file dropped into a charter
directory, or a charter directory reached through <charter-dir>, lands
verbatim inside a fence the provenance preamble declares
repository-sourced. Each emitted path is now probed with the exported
neutralizeFenceTokens so a hit raises CONTEXT_PACK_FENCE_COLLISION
naming the specific path (fenceBlock's single collided flag cannot say
which path collided). The resolved title is neutralized before
interpolation. No new error code. files[] deliberately keeps the real
on-disk paths, since it is the list a reviewer opens.

Body-side only. Fence-header attribute values remain unneutralized --
deferred to adev-plugin-j7pq.7 (SEC-1). Acceptance criterion 6 is
partly, not fully, satisfied.

The gap is pinned as an executable marker: a test named for
adev-plugin-j7pq.7 asserts TODAY's escapable-attribute behavior, so the
day j7pq.7 lands the assertion flips and forces a deliberate update.

Also fixes three Minor comments from the Task 4 review at the same site:
the manifestTitle comment now describes the ?? semantics accurately, the
inline Pass-2 banner is qualified, and the two competing header
representations on a no-matches unit are documented.
