## Intent

docs(review): rev-5 amendment revision 2 — address six review blockers

Full-tier review BLOCKed revision 1: all three specialists returned FAIL, 20
findings, 6 blockers. Revision 2 addresses all six. Content was authored by
hand and `adev specify revise` run afterwards for the mechanical bookkeeping
only — see the note at the end.

SA-1 shared-consumer blast radius. The real design error. BEH-2/BEH-3 stated
the delivery-model change unconditionally on `renderPack`, which is shared with
configurable-checks; rev-4's 22o deliberately keeps `base` target-agnostic and
widened it for five constitution-compliance checks in validate.yaml. A
manifest-only `base` with no targetSpecPath inlines nothing, silently reversing
22o. Fixed by making delivery an explicit per-pack `delivery: inline|manifest`
declaration (BEH-9) that DEFAULTS TO INLINE and inherits through
resolveExtends, so every existing consumer is byte-unchanged unless it opts in.
Only `review-base` declares manifest. Added an explicit "Behaviors narrowed"
table stating the effect on 22k/22l/22m/22n/22o/22p-bis rather than leaving it
implicit.

SA-2 + CON-2 contradictory truncation contract. The target spec was specified
as both byte-exact and truncatable, and the oversize row invoked 22l (the
per-file cap BEH-2 exempted) while naming max_total_bytes as the trigger, then
labelled the result with 22m's role="truncation-notice" — a case 22m never
covered. Resolved by picking one semantic: the target spec is exempt from BOTH
caps and is never truncated (BEH-12). TARGET_SPEC_OVERSIZE is now a pure
warning with no truncation and no marker. 22l and 22m keep their rev-4 meanings
untouched.

SA-3 + SEC-1 undefined manifest form / path injection. The manifest's rendered
shape was unspecified, which left BEH-7 contradicting 22j's rule that unfenced
text is never actionable, and made the forgery acceptance criterion
unfalsifiable. Worse, paths become the sole non-target-spec content channel and
`<charter-dir>` plus sibling filenames are author-controlled. Fixed by reusing
22g's existing section mechanism — one nonce-fenced section per include with
role="path-manifest" and a title attribute, title falling back to the glob
string then omitted, `<no matches>` preserved — so there is no new grouping
syntax to forge (BEH-10). BEH-14 routes every emitted path through 22h's
fence-token neutralizer. The body-forgery criterion is replaced with one
asserting a file or directory NAME cannot forge a section.

CON-1 denylist severity split. BEH-4 invented two codes that exist nowhere in
the repo and collapsed rev-4 22p-bis's three-way split, downgrading an
ENUMERATED include resolving to a secret from hard failure to a warning — the
symlink-evasion regression. Fixed by deleting both invented codes and reusing
22p-bis verbatim (BEH-11): CONTEXT_PACK_DENYLIST for a denied literal pattern,
CONTEXT_PACK_DENYLIST_SKIP (warning) for a wildcard match,
CONTEXT_PACK_DENYLIST_MATCH (hard error) for an enumerated match.

Also acted on two non-blocking findings both reviewers reached independently:
BEH-8 now claims AUDITABILITY rather than reproducibility, since the dispatch
record cannot bound reads outside the manifest and bare paths carry no content
hashes. I had overclaimed.

Behavior IDs: BEH-2, BEH-3, BEH-4 and BEH-6 are TOMBSTONED rather than
reworded, because each had the condition it governs changed (from
unconditional-on-any-pack to conditional-on-delivery). A finding filed against
BEH-3 now resolves to a tombstone instead of unrelated text, which is the
convention's intent. Live set is BEH-1, BEH-5, BEH-8, BEH-9..BEH-14.

METHOD NOTE. `adev specify revise` never edits spec body content
(adev-plugin-revise-loop-no-content-edits-q6q0, open P1) yet reports every
blocker addressed, which normally writes false provenance. Here the content
edits were authored by hand FIRST and the verb run second purely for the
revision bump, status transition, sidecar clearing and spec_revised event — so
its addressed_blocker_ids: [all 6] is accurate rather than fabricated.

Base spec verified immutable. Suite 7077/7035/10, unchanged.
