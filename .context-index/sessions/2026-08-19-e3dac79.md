## Intent

fix(cursor): make the containment guard testable, and actually test it

Round 4 of review: 1 blocker, 5 warnings, 1 suggestion.

BND-1 / WIR-9 (blocker, found independently by two reviewers in different
lanes): the regression test written for round 3's containment fix never ran
the guard. publishSkillsFromCache is module-private, is async, and derives its
target from getCursorHome() — and install() returns early when the cache
exists, so publish only runs against a cache populated from the real plugin
root, which a test cannot poison. The test therefore always took a fallback
branch that grepped the adapter SOURCE for three identifiers. Those match
anywhere in the file, including a comment, so it would have passed against a
guard declared but never called, called after the write, or logically
inverted. Its own comment claimed the fallback existed "so this test cannot
silently pass"; the fallback WAS the silent pass.

  - the decision is now the exported pure function resolvePublishTarget, so
    the real behaviour is reachable without a full install
  - the one remaining source-scoped assertion is the ORDERING check — that the
    guard precedes every write — which is a property of the call site that no
    unit test of a pure function can observe, and it is scoped to the function
    body rather than the whole file

BND-2: the guard compared paths lexically and never called realpathSync,
omitting the step from lib/extensions/exec-payload.mjs::assertContained, the
primitive its own comment cited as the model. That primitive's header
documents why: a symlinked root (dotfile managers commonly create one, or it
can be planted before install) defeats a lexical check while ensureDir/cpSync/
writeFileSync all follow the link.

FALSIFIED, which is the part that mattered: three reintroduced defects each
fail the suite — allowlist disabled (2 fail), containment made lexical
(3 fail), unresolvable root allowed (1 fail) — with every probe asserted to
have actually applied. That caught a FOURTH vacuous guard: the first repair
still passed with the allowlist disabled, because the test never created the
skills root, so realpathSync failed and every input threw SKILL_PATH_ESCAPE
for a reason unrelated to its name. Added the adev-a/b case specifically —
it resolves INSIDE the root, so only the allowlist rejects it, and without it
the suite could not tell whether the allowlist existed at all.

Also from round 4:
  - WIR-8: Error Cases rows for both new failure modes, naming their distinct
    signal shape (an entry in the failed[] array, not an exception)
  - CON-1: the acceptance criterion, added only after the test became real
  - RI-1: test-file counts re-derived (99 modified, 5 added, 4 in scope), and
    the added guards itemized rather than listing one of four
  - RI-2: the issue board is now on this branch, so the ids this spec cites
    resolve in the tree it ships in — they existed only in the main worktree
  - RI-3: reviewer citations qualified by round, since ids are round-scoped
    and BND-4 means different findings in rounds 2 and 3; and .review.md now
    covers all four rounds rather than round 1 alone, which is a skill step I
    had been skipping since round 1
