## Intent

fix(ci): skip GitHub auto-merge commit in provenance trailer check

The provenance check on pull_request runs iterates `origin/<base>..HEAD`,
which includes the auto-generated `Merge <pr-head> into <base>` commit
GitHub Actions creates at HEAD for PR runs. That commit doesn't carry
`Author-type` / `Operator` trailers because the trailers come from the
local pre-commit hook, which doesn't run on GitHub's server-side merge.

Result: every stacked PR fails the trailer check on its pull_request
run while the push run (which doesn't run the check) passes.

Two changes to the trailer loop:

1. Use `git log --first-parent` to walk only the PR-side commit chain
   (the merge commit's first parent is the PR head; the second parent
   is the base ancestor we already trust).

2. Move the `Merge */fixup!/squash!/amend!` skip from inside the
   conventional-commit check to the top of the loop, so merge commits
   skip BOTH the trailer check and the conventional-commit check.

PR #106 was masking this — its `pull_request` run is the same
commit-iteration logic; it only "passed" because GitHub Actions
reported the push run (which skipped the provenance step entirely)
ahead of the pull_request run.
