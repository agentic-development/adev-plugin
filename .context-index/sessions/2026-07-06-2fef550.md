## Intent

fix(lib): parseFrontmatter drops frontmatter when a marker/heading precedes the fence

parseFrontmatter anchored its match to /^---\n/ (^ at byte 0, no /m flag),
so any spec/charter opening with a `<!-- partial_schema: spec@1 -->` marker
or a `# heading` before the `---` fence parsed as having NO frontmatter —
kind/status/revision/charter all silently defaulted. This affected 127/229
specs and produced false MISSING_KIND/LEGACY_DEFAULTED findings in
/adev:hygiene Pass 18.

Strip a leading run of HTML comments, headings, and blank lines before
matching the fence, so frontmatter is read regardless of a leading preamble
while a `---` thematic break in the body is never mistaken for frontmatter.
The un-anchored pattern already used by lib/spec-drift.mjs is why Pass 17
read correctly. Adds 4 regression tests to tests/lib/meta-tools.test.mjs.
