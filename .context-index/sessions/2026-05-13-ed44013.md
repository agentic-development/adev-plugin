## Intent

fix(agent-reliable-state-artifacts): migrateMilestones writes worktree-local, not main-checkout

Previously migrateMilestones resolved its target path via resolveStorageRoot(),
which in a worktree returns the main repo's root. That meant running
`adev migrate` from a worktree silently wrote milestones.json into a sibling
worktree's working tree — invisible to the branch the operator was on, and
potentially mixing up commits across branches.

Other migrators (tasks, lifecycle-state, constitution, plan-advisory) already
wrote worktree-local. Milestones was the inconsistent one.

Fix: migrateMilestones target is now `<projectRoot>/.context-index/milestones.json`,
written via the migrator's local atomicWriteJson helper, bypassing
saveMilestones() (which uses resolveStorageRoot at runtime — that's correct for
read-time worktree-shared semantics, but wrong for one-time write-time migration).

The runtime helpers (loadMilestones / saveMilestones) keep their existing
resolveStorageRoot-based design — worktree-shared storage still works at
runtime. Once the migration commit reaches the main branch, the main checkout
has milestones.json at the path resolveStorageRoot() returns, so reads succeed
in every worktree.

Also includes the previously cross-worktree-placed milestones.json moved into
this worktree (where it belongs). The accidental copy in the main checkout was
deleted (it was untracked, no commit impact).

Regression test added: assert.equal(result.target, join(root, '.context-index',
'milestones.json')).

All 2446 tests pass.
