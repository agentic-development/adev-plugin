## Intent

chore(issues): file issue-529 — configurable PR body composition

Surfaced while merging fix/lifecycle-cleanup-and-sidecar-foundation:
adev's validate and implement skills both emit a literal "Ready for
PR. Run: gh pr create --base <target-branch>" line with no body, no
flag, and no template reference. The CLI has no `pr` verb and the
manifest's `repo:` block carries no `pr_template:` knob. Confirmed
absent by grep across .context-index/, skills/, lib/, cli/ — zero
hits for pr_template / pr-template / prTemplate.

The data needed for a useful PR body is already structured by the
time validate finishes (spec title, validate verdict + check tallies,
behaviors, commits filtered by Spec: trailer, reviewer notes,
source-manifest sha). Only the rendering layer is missing.

Proposed shape mirrors the `adev route render-sidecar` pattern that
the rev-2 JSON sidecar migration just established: an
`adev pr body --spec <path>` CLI verb wrapping `lib/pr-body.mjs`,
with an optional `repo.pr_template:` manifest knob pointing at a
customizable template file. Built-in fallback so the unconfigured
case works out of the box. /adev:validate emits a copy-pasteable
`adev pr body | gh pr create --body-file -` line on PASS.

Issue body includes the full acceptance-criteria draft (7 items) and
explicit out-of-scope list (push, auto-merge, issue cross-linking).
