## Intent

feat(work): stop the conductor re-loading skill bodies already in context

adev-plugin-04jr.1, approach 3 -- the only part of skill-load deduplication
that is fully inside this repo's control.

Measured on one lifecycle: `specify` was loaded three times and `work`
twice, ~31K tokens of duplication. Two of the specify loads and both work
loads came from Conductor Mode re-entering skills it had already run. A
re-loaded body is not paid once: it joins the context prefix and is
re-read on every subsequent turn, so the cost is multiplied by the
remaining turn count.

A skill cannot detect from inside itself that its body is already in
context -- there is no introspection surface for the prompt -- so an
instruction in the router is the only available lever. Conductor Mode now
forbids re-invoking /adev:work to advance the arc and re-invoking a target
skill already run for the same unit of work, and names the two sanctioned
ways to run a stage again: continue from the instructions already in
context, or dispatch it as a subagent, which runs in its own context
rather than appending to the orchestrator's.

The rationale is kept in the skill on purpose. Stripped of it the rule
reads as style advice and gets simplified away, and the duplication then
returns silently because nothing else in the system can observe it.

This does NOT address the general case: a direct second invocation of a
skill by the user still re-injects the body. That needs harness-level
dedup, outside this repo. adev-plugin-04jr.1 stays open for it.
