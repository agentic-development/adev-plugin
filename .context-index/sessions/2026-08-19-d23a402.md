## Intent

test(evals): add specify scenario + relocation fidelity, from a both-trees comparison

Ran the same audit pass against the monolithic body on main and the split body
on this branch, over an IDENTICAL audit target so the only variable was the
skill surface. Result, and what it does and does not establish:

READS — the mechanism works.
  main(mono)   : skills/hygiene/SKILL.md
  branch(split): skills/hygiene/SKILL.md + references/audit-passes/pass-12-*.md
The split agent followed the pointer and opened exactly one of 23 companions.

OUTCOMES — diverged. Monolithic produced 3 findings (REALITY_DRIFT,
REVISION_DRIFT, FILE_DRIFT); split produced 1 (FILE_DRIFT) and skipped reality
drift saying "adev verify spec unavailable in audit context".

That looked like a regression until the content was checked: Pass 12 is
byte-identical across the refactor apart from one trailing newline, and the
companion carries every finding type including the one the split run skipped.
So the divergence was the model declining a step it HAD been given, not
instructions that went missing.

The methodological finding matters more than the result: outcome comparison at
n=1 is NOT a usable regression signal for skills, because model variance
swamps it. Two single runs cannot separate signal from noise. What IS usable is
cheap and deterministic — content equivalence and load behaviour.

So the comparison became a test rather than a one-off:

  relocation-fidelity.eval.mjs — asserts prose moved into a companion is
  byte-identical to the prose it replaced in the pre-split body, recovered via
  `git show main:...`. This is the strongest available statement that a
  relocation changed nothing, and it is exactly what a prose-presence test
  CANNOT make: that only asks whether a string exists somewhere. Falsified
  against a single altered token and a 10-line truncation.

  specify --extract scenario — the largest disclosure claim in the refactor
  (7 mutually exclusive modes, 19,888 B of Standard Mode alone). Observed: the
  body, the ONE mode the flag selects, and the two shared/ companions that
  apply to every mode. None of the other six, including standard-mode.md, the
  default-path companion most likely to be grabbed by habit. Falsified against
  wrong-mode, all-seven-modes, dropped-shared, and no-companion.

  since() now takes {skill} so concurrent captures stay separable — the
  tracking log is shared and has no per-agent key, so a capture window alone
  cannot tell two simultaneous runs apart.
