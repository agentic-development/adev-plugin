## Intent

test(extensions): add 11 runtime-behavior tests for example-validation-check

Complements the existing install-side coverage with end-to-end
behavioral tests that exercise the runtime path /adev:validate actually
takes after install. The original test set proved install correctness;
these new tests prove the contract THE DOCS DESCRIBE actually holds at
runtime.

Coverage added:

  Behavior 2 — install + PATH_TRAVERSAL inheritance
    · "install rejects a manifest whose hook source escapes the source
      dir" — accepts PATH_TRAVERSAL or ENOENT (both prevent the
      malicious source from landing)

  Behavior 3 — runtime execution + projection roundtrip
    · "installed check executes via runQualityGate and returns PASS" —
      reads the merged entry from validate.yaml, invokes
      runQualityGate with the canonical ctx (cwd=projectRoot,
      env={}, parentEnv=process.env, timeoutMs=5000), asserts
      status=PASS, exitCode=0, redactedStdout contains the canonical
      PASS line, redactedStderr empty. This is the actual execFile
      path /adev:validate takes — the fold-in coverage gap surfaced
      by the rev 2 reviewer is closed.
    · "validator_report event surfaces in currentState projection" —
      walks specify→review→plan→implement→validate via adev report
      --type step, emits a validator_report via the CLI, then reads
      `currentState(...).steps.validate.reports[]` and asserts the
      event surfaces in the projection with stamped severity + ISO
      timestamp. Proves the lifecycle-event-log → projection path
      end-to-end, not just the raw log.
    · "adev report --type validator is silent on success" — stdout
      empty; stderr allows only the two documented severity-resolution
      advisories (UNKNOWN_VALIDATOR_DEFAULTED, DOMAIN_CONFIG_DEGRADED)

  Behavior 4 — bin/check.sh runtime contract
    · "ignores trailing argv noise" — 7 different argv sets (including
      shell-escape attempts); asserts identical stdout regardless of
      argv and that the SECRET env var sentinel doesn't leak
    · "exits 0 even when invoked from a different cwd" — cwd-locking
      independence (configurable-checks Behavior 6c semantics)

  Pitfall enforcement (docs/extensions.md)
    · "validate-load rejects governance entry missing profile: on
      quality-gate" — configurable-checks Behavior 13
    · "install rejects manifest with unsatisfiable requires.adev range"
      — pinned ">=99.0.0", asserts INCOMPATIBLE_ADEV_VERSION
    · "install rejects governance entry missing id" — accepts either
      install-time throw or validate-load rejection

  Template installability
    · "template installs successfully (proves it's a working manifest)"
      — builds a real manifest derived from the template's documented
      shape, installs against a temp project, asserts validate.yaml
      gains the entry
    · "template enumerates all 5 provides.* slots as readable YAML
      examples"

Product behaviors surfaced while authoring (test code, not product code):
  1. runQualityGate returns { redactedStdout, redactedStderr }, NOT
     { stdout, stderr } — test uses the canonical fields.
  2. DOMAIN_CONFIG_DEGRADED advisory appears alongside
     UNKNOWN_VALIDATOR_DEFAULTED when the project has no per-domain
     gates config. Documented advisory, not a failure.
  3. Missing requires.adev is permissive (no constraint); the real
     pitfall is an unsatisfiable range.
  4. PATH_TRAVERSAL guard for missing source paths fires ENOENT
     before the canonical traversal check; both outcomes prevent
     the escape, so the test accepts either rejection code.
