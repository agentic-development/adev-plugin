## Intent

ci: auto-propagate main into release/next for pre-releases

Add a workflow that merges main into the long-lived release/next branch
on every push to main, so release-please keeps the X.Y.Z-next
pre-release PR current without a manual merge. Automation only advances
the branch — publishing still requires merging the pre-release PR by
hand.

The merge is always a merge commit (release/next carries a branch-only
prerelease-config commit, so it can never fast-forward), and the
three-way merge preserves release/next's own release-please-config.json.
The job aborts loudly on conflict or if "prerelease": true is lost,
rather than risk publishing a stable version to the next channel.

Documents the required RELEASE_PLEASE_PAT secret: a push made with the
default GITHUB_TOKEN does not trigger downstream workflows (GitHub's
recursion guard), so without a non-Actions token the branch would
advance but the Release workflow would never re-run to update the PR.
