## Intent

chore(validation): populate governance/validate.yaml from domain starter

Copies the six check entries from templates/domains/software/validate.yaml
into the previously-empty project registry (issue-507). Under the
single-source model (validate-config-single-source.spec.md), the project
file is authoritative; until this commit it declared `checks: []`, which
left /adev:validate without a registry-driven check set.

Entries added:
- validate.check-1.5-source-manifest    (deterministic-check, warning)
- validate.check-2-spec-compliance      (subagent-review, error)
- validate.check-4-constitution         (subagent-review, error)
- validate.check-8-boundaries           (subagent-review, error)
- validate.check-9-transition-gates     (subagent-review, warning)
- validate.check-11-visual-verification (subagent-review, warning)

Verified that `loadValidateConfig(projectRoot)` now returns the populated
list with no errors. Three warnings surface for the browser-review profile
(playwright + read-only network broadening) — those are inherent to the
visual-verification profile, not introduced by this change.

Note (not covered by this commit): the third acceptance criterion in
issue-507 — "no more UNKNOWN_VALIDATOR_DEFAULTED warnings" — does NOT
hold after this fix. Investigation revealed that lifecycle-state's
_resolveActorSeverity looks at gates.yaml (not validate.yaml) for
validator severity stamping. Silencing those warnings requires a
separate severity-resolution change. Issue-507 will be updated with
this finding before close.

The drift_detected stamp on check-set-restructure.spec.md is correct
hook behavior — the spec's source-manifest covers governance/validate.yaml.
