## Intent

fix(templates): emit frontmatter before the H1 in all six spec templates

Every spec template opened with an H1 and a comment block above the `---`
delimiter. `lib/diagnostics/tier1/frontmatter-present.mjs` rejects any
markdown body before the delimiter, so every spec scaffolded from a
template fired an error-severity diagnostic: 128 of 235 spec files in
this repo, and roughly 400 artifacts once reviews and validations are
counted.

This is not cosmetic. `adev specify revise` could not parse those specs
at all — it failed with `INVALID_SPEC_PATH: spec missing or malformed
revision: frontmatter field (got undefined)` even with `revision: 1`
plainly present, because the frontmatter did not start at line 1. Since
`--revise` is the prescribed path out of a BLOCK verdict, the
review-block-auto-retry loop could not run on any template-authored
spec. Reproduced live on measurement-integrity.spec.md; moving its
frontmatter to line 1 made the identical command succeed.

The four charter templates already did this correctly and produce zero
violations, which is what identified the templates as the cause rather
than the artifacts.

Change is a pure reordering — frontmatter block first, then the H1 and
its comment, then the body. Verified content-identical modulo blank
lines for every file.

Tests: tests/templates/frontmatter-first.test.mjs asserts the first
non-blank line of all ten spec and charter templates is `---`, and
scaffolds a spec from each spec template to assert it passes the
diagnostic. End-to-end check: a spec scaffolded from the fixed
behavioral template now revises cleanly (rev 1 -> 2).

Does not backfill the ~400 existing artifacts — that is issue-587,
deliberately sequenced after the producers are fixed so the sources stop
regenerating violations.
