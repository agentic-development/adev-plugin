## Intent

feat: add reviewer-domain-fit initiative charter

Initiative charter for adev-plugin-j7pq.5. adev ships one hardcoded review
panel scoped to web-application concerns and applies it to every project. All
23 security-shaped issues on this board match path containment, subprocess
interpolation, input trust, privilege posture, artifact leakage or destructive
fs; zero match any OWASP scope the panel reviews.

Two tracks. The evidence track is gate-conditional: declare referent-integrity
alone, run against five pre-fix specs with known root causes, and stop if fewer
than 3 of 5 are caught with resolving citations. The enablement track is
unconditional — inline prompt bodies, a web-service domain owning the OWASP
prompt with plugin shims, install-time registry validation, split load-failure
semantics, codebase-shape domain detection at init, `adev governance adopt` as
Pass 19's apply path, and unbundling `software` into a vendored
default-installed extension.

Two corrections made during the brainstorm, both from operator challenge:

- An earlier draft claimed a <source-manifest> token would make existence
  questions answerable. False: reviewers extend read-only, which grants
  filesystem-read and search repo-wide, and they demonstrably read source
  unprompted (five rounds cited lib/cli/gate.mjs:144, effectiveRevision(),
  parseFrontmatter's indent-0 limit). The token buys determinism, not
  capability, so the gate now runs FIRST and the token is decided on eval data.
- An earlier draft treated keeping the OWASP prompt files in the plugin as a
  constraint. It is not: resolveReviewerPath accepts relative paths under
  .context-index/, which is where extensions merge domain profiles. The real
  constraint is backward compatibility with materialized registries, which
  shims plus `governance adopt` address.

Filed while brainstorming: xg1f.4 (data-engineering extension breaks review on
install — inline prompt prose resolved as a file path, aborting the whole
registry), zsmh.3-.6 (the deferred extension-lifecycle features).

Product.md Module Map intentionally not appended: it lists architecture
components with a Key Files column, not charters, so an initiative row would
misrepresent the table.
