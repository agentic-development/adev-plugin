## Intent

feat(review): render path-manifest sections for delivery: manifest packs

A pack resolving to `delivery: manifest` now emits one nonce-fenced
`role="path-manifest"` section per include, in declaration order, whose body
is one repo-root-relative path per line sorted in byte order (BEH-10, BEH-5).
No matched file's body is inlined: the target spec is supplied separately by
`buildReviewerDispatches` under the same nonce, so inlining it here would ship
the spec twice.

Pass 1 now carries `includeIndex` and the resolved manifest `title` on every
plan unit; the inline branch ignores both and stays byte-identical to rev 4.
No `role="truncation-notice"` is emitted for a manifest pack and no file is
dropped for budget reasons. A manifest pack rendered with no `targetSpecPath`
now fails load with the existing `CONTEXT_PACK_NO_TARGET` code, independent of
whether any include carries a target-relative token.
