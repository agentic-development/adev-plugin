## Intent

fix(specs): make stale figures and contradicting sections impossible, not rarer

Two classes produced most findings across five review rounds. Both were
structural, and both had been "fixed" by promising more care — which failed
four consecutive times.

STALE FIGURES (revisions 3, 4, 5, 6 — one per round). Every instance had the
same cause: a figure measured, then a later edit in the same commit moved it.
Nothing but a reviewer's arithmetic could catch it.

tests/skills/spec-figures-current.test.mjs now parses the tree-tracking figures
OUT OF THE SPEC PROSE and recomputes each from the repository — the current
byte total, the saving (quoted in two sections, which is how it drifted), the
percentage, the per-tree companion count, and pointer occurrences/unique
targets. Editing the spec to a new correct value passes; editing it to a wrong
one fails. Falsified against all six historical failure modes, including the
exact rev-6 case where a 5-line edit to plan/SKILL.md moved the total by 270 B.

Deliberately NOT pinned: the 856,056 B baseline and the sixteen "before" values,
which are history and cannot drift. Deliberately REMOVED: the suite total.
Asserting the suite's own size from inside the suite is circular, and the
absolute number is not evidence for "the gates pass" — which is the actual
claim. It drifted in four straight revisions; deleting it ends that.

CONTRADICTING SECTIONS (six findings, most recently CON-1 in round 5). The
Error Cases table and the Known-gaps list both carried guard status, so every
fix had two places to be right and kept landing in one. The table now names the
SIGNAL a failure produces and defers status to Known gaps, which is its single
home. A header says so, so the next editor does not reintroduce the split.
