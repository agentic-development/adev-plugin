## Intent

docs(review): revise rev-5 review-gate amendment to rev 4 — address three rev-3 blockers

SA-1 (structural-architect:contradictory-contract:72233b01) was my own editing
error: the rev-3 patch replaced BEH-1's scope clause but left rev-2's sentence
"the exact byte range following the second --- line" in place, so BEH-1 defined
its digest input twice, incompatibly, and the acceptance criteria inherited the
split. BEH-1 now carries one definition and says so explicitly.

SEC-1 (no blocker_id — LEGACY_REVIEWER_OUTPUT, carried across by hand from the
.review.md since it was excluded from the sidecar): rev 3 serialized the
frontmatter half of the attested region as raw `key: value` source lines. With
no YAML library in this repo, a block scalar or quoted multi-line value can
serialize to the same bytes as two separate keys, colliding two different
governance states onto one spec_sha — a CWE-436 interpretation conflict feeding
the CWE-345 hole the amendment exists to close. New BEH-1b requires serializing
PARSED values via `key + ": " + JSON.stringify(value)`, which cannot alias.

SA-2 (structural-architect:unenforceable-invariant:8efa0bef): rev 3 scoped
reconciliation to "the latest revision of that step", but no emitter stamps a
revision on reviewer_report — `adev report --type reviewer` has no --revision
flag, so all nine reports across three review rounds sit in byRevision["1"] and
"latest revision" degenerates to whole history, reintroducing the permanent
"divergent" latch. BEH-3a now defines the window as the reports appended after
the most recent spec_revised event, which `adev specify revise` already emits
with from_revision/to_revision — computable from data the log carries today,
with no new emitter field.

Acceptance criteria 21 -> 24. Behaviors 13 -> 14 (BEH-1b).
rev 3 -> 4, sidecar cleared. adev diagnose clean.
