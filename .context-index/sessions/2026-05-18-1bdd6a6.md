## Intent

test(spec-drift-detection): two-branch concurrent stamp merges without conflicts (headline acceptance)

Headline acceptance test for jsonl-drift-events.spec.md Behavior 8 — the
exact merge scenario the whole refactor exists to fix.

The test reproduces the bug:
  - Create a spec with source-manifest tracking two files.
  - Branch A: stampDrift(spec, "lib/a.mjs"); commit.
  - Branch B (from main): stampDrift(spec, "lib/b.mjs"); commit.
  - Merge branchA into branchB.

Pre-refactor: spurious content conflicts on the spec frontmatter's
drift_source / drift_at lines (overwriting the same offset with different
values). Post-refactor:
  - Spec frontmatter has byte-identical `drift_detected: true` only →
    git's three-way merge auto-applies the "both added" line.
  - Per-spec JSONL has disjoint appends from each branch → resolves
    cleanly when declared `merge=union` in .gitattributes.

Adds a project-root `.gitattributes` declaring
`.context-index/lifecycle-state/*.jsonl merge=union`. The integration
test mirrors this attribute into the test repo so it exercises the same
production merge semantics. Without `merge=union`, git's default
three-way merge would conflict on any two-branch append even though the
added lines are disjoint events — `merge=union` is the canonical
git-native primitive for append-only logs.
