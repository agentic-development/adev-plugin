## Intent

fix(execution-state): close the two shadow-path sites the shared root exposed

Making execution state worktree-shared left two callers still hand-building
<projectRoot>/.context-index/.execution-state.json. Both are load-bearing.

lib/session-capture.mjs (two sites) read that path directly, so after the
resolver change it read a worktree-local file the writer never touches — a
session in a linked worktree would silently record a stale or missing
issue/epic binding. Now routed through readExecutionState via a lazy import
that returns null on any failure, since a capture hook must never break the
tool call it observes.

lib/migrate-state-artifacts.mjs was worse: migrateExecutionState checked for
an existing target at the LOCAL path, wrote through writeExecutionState to
the SHARED root, and reported the local path back. Run from a worktree, the
"already migrated → skip" guard therefore never fired and the migration
overwrote the main checkout's live session state. Resolving the target from
the same storage root is what makes that guard protective.

That fix is deliberately the opposite of migrateMilestones() directly below
it, which stays worktree-local on purpose — and the difference is real, not
an inconsistency: milestones.json is git-tracked, so writing it to the main
checkout would contaminate a sibling branch's working tree (the 0.26.0
surprise its comment records). .execution-state.json is gitignored transient
state, so that hazard does not apply and coherence with the runtime reader
wins. Both rationales are now written down at their respective call sites.

The two session-capture fixtures gained a manifest.yaml. That is not a
weakened assertion: readExecutionState requires a manifest before resolving a
root, the beads fixtures beside them already wrote one, and session-capture's
own validateCwd enforces the same precondition in production — the file-backend
fixtures were the ones modelling an impossible project.

The migration test was checked non-vacuous: both assertions fail against the
pre-fix module and pass after.
