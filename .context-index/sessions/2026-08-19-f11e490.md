## Intent

fix(skills): resolve the five review blockers, spec to revision 2

Two were defects in the shipped tree and are fixed in code, not described away.

BND-1 / WIR-1 — codex and opencode mirrors shipped ~155 broken pointers.
Root cause was narrower than "companions were not mirrored":
sync-provider-skills.mjs DID sync companions, but globbed flat `*.md` at the
skill root. When they moved into references/, that filter silently stopped
matching anything while the same script kept regenerating mirror bodies full
of pointers to them. Both adapters symlink the mirror directory into user
installs, so the skill lost its instructions with no error raised.

  - the companion sync now walks references/ and scripts/ recursively
  - all three trees carry an identical 206-file companion set
  - tests/sync/provider-companion-parity.test.mjs pins the property directly
    rather than deriving it from the tool it guards, which is why the existing
    parity test could not catch this: it runs the sync script in --dry-run and
    a sync that copies nothing reports no drift. Falsified by deleting one
    mirror companion — both new assertions fail.

BND-2 — Invariant 3 mandated `skills/<name>/references/...`, which is
repo-root-relative and unanchored at every install surface (cursor renames the
directory, copilot and codex publish elsewhere, and in a user project the
agent's cwd is the project root). 183 pointers re-anchored to
<ADEV_ROOT>/skills/..., the convention the repo already had and used for one
companion. Tests that resolve a pointer FROM the prose now go through
resolveSkillPointer(), performing the same substitution an agent does, so they
keep exercising the indirection instead of hardcoding the target.

TERM-1 / TERM-2 — BEH-9's re-run escape was uncapped. build.max_retries and
build.max_review_retries do not bound it: they are decremented inside build's
own state. /adev:work now caps conductor-driven re-runs at 3 per stage, states
the cap-trip verdict (stop and report, do not switch strategy and continue),
and makes the unattended default stop at the FIRST failure — the confirmation
gate reads "before invoking a skill", and an in-context continuation is not an
invocation. Also states that loading a companion is a continuation, not a
re-entry, which resolves the collision with BEH-4.

RI-1 — all five Landed: SHAs were orphaned by the filter-branch that
re-stamped this branch's Spec: trailers. Replaced with the reachable commits.

Also fixed, from the warnings: the routing assertion added to prove companions
stay wired read the concatenated surface and would have passed against any
companion, violating the rule stated in tests/helpers.mjs by the same change
that wrote it; `## Prerequisites` was the one Invariant-2 class with no
body-scoped guard and now has one; the Copilot blast radius was overstated
(buildPlan is called only from install); and every count and byte figure is
re-measured against the shipping tree.

Spec is revision 2, status review-pending, with two previously-false
acceptance criteria now carrying the guards that make them checkable.
