## Intent

fix(plan-immutability): only flag genuine modification commits

detectMutatedPlans previously called `git log -1 --format=%aI` without
a diff filter, returning the addition commit's author date for any
tracked plan file. When a plan was authored (emitting `plan_task pending`
events) and committed in a separate later commit, the detector would
read commit-time > pending-time and false-positively flag the plan as
"modified after pending". This affected every plan committed normally,
including all 11 lifecycle-artifacts plans.

Fix: check `git ls-files --error-unmatch` to determine if the file is
tracked. For tracked files, use `git log --diff-filter=M -1 --format=%aI`
so only real modification commits count; an empty result signals "never
modified post-creation" → no violation. For untracked files (test
fixtures, freshly authored), fall back to file mtime as before.

The static violation fixture at tests/fixtures/plan-immutability/violation
is now tracked by the parent repo and no longer triggers under the new
logic. Replaced the violation test with a dynamic temp-dir setup that
writes an untracked plan + lifecycle log and bumps mtime past the
pending event ts.
