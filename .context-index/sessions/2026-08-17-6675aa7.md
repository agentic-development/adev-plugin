## Intent

test(review): assert 22p-bis denylist parity for manifest entries

Test-only for behavior: no production logic changed. The Pass-1 denylist
filter runs before the manifest branch groups anything, and Task 4
already sourced both the manifest body and files[] from the
POST-denylist safe set, so the distinguishing claim -- 'the denied path
is never NAMED' -- held already. It is now pinned so a later refactor
cannot quietly re-source the body from the pre-filter match set.

All three denylist codes are reachable and each is asserted positively.
CONTEXT_PACK_DENYLIST_MATCH is reached by an enumerated include carrying
a TRAILING SLASH: expandGlob normalizes separators via
split('/').filter(Boolean) so the walk still resolves the file, while
isDenied is regex-anchored on the raw glob string and cannot match
through the trailing '/'. No wildcard and no symlink needed, so the
enumerated half of the severity split is now asserted end to end rather
than assumed. Separately asserted, as its own distinct behavior: a
symlink to a denied file is silently unmatched, because expandGlob
filters on lstat-based Dirent.isFile().

Also asserts rev-4 inline behavior is retained verbatim for the same
three fixtures (same codes, same severities) rather than assumed, and
freezes the module's declared code vocabulary at source level so adding
a code trips the suite even when no fixture reaches it.

No new denylist code. Two gaps are pinned as failing-on-fix markers
asserting today's behavior, both deferred to adev-plugin-j7pq.7:

  - SEC-2: BEH-11's 'a denied path is never named' is not entailed for
    control-character paths.
  - A DENYLIST_MATCH include whose denied file was its ONLY match leaves
    safe.length === 0, so a no-matches section is emitted whose header
    carries the glob string and rendered is non-empty while errors is
    non-empty. This is INHERITED rev-4 behavior, not rev-5 drift -- rev 4
    named the same glob in path= -- and BEH-11 requires the split be
    retained verbatim while forbidding new codes, so it is out of scope
    here. The only production change in this commit is the comment
    recording that at the site.
