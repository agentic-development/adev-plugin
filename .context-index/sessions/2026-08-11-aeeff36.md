## Intent

docs(test-strategies): fix inverted task-region mapping + round-8 warnings

SA-48/SEC-33 (verified: incremental-artifact-writes.plan.md has "### Task 1
Context" at line 51 and the body "### Task 1: ..." at 145 with Files at
149): the round-7 mapping opened at the first "Task N" heading, which in
the shipped template is the context packet, leaving **Files:** outside the
region for essentially every task — the sensitive-path leg would have been
dead corpus-wide, and newly authored plans would degrade identically,
falsifying the decision note's "degraded population only shrinks" premise.

The mapping now distinguishes the two heading families: a task-body heading
matches ^#{2,4}\s+Task <N>\b with no "Context" in the remainder (the body
form carries a colon, context headings never do); the region opens at the
first body heading for N and closes at the next body heading for a
DIFFERENT task number or EOF, so same-task sub-headings (Task N — Tests)
stay inside and context-family headings never open or close a region. The
AC now asserts against a template-emitted plan (region must contain the
Files block), not against the regex, so a conforming-but-wrong
implementation cannot pass.

Also: decision note re-derived and its stale "third floor state"/(Task Map)
references fixed (CON-51/SEC-34); floor_legs added to the four remaining
enumerations — error row, floor postcondition, two Task Map rows (CON-53);
ADR's two lowercase tests: references converted (CON-52).
