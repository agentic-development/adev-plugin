## Intent

feat(validation): atomic write for .validate.md + check-12 prefix disambiguation

epic-85 / issue-496 — Atomic validate report write
  New verb `adev artifact commit --spec <p> --kind <validate|review>`
  resolves source = <spec>.<kind>.md.tmp and destination = <spec>.<kind>.md,
  validates the temp file exists and is non-empty (rejects zero-byte
  artifacts from truncated writes), then performs a same-directory
  `fs.renameSync` — atomic on POSIX. Solves the failure mode hit during
  the 2026-05-16 validation charter build retro, where a socket closure
  during validate left the canonical .validate.md missing on disk even
  though all validator events fired.

  /adev:validate's Report Format section now instructs the skill to
  write to <path>.validate.md.tmp via the Write tool, then commit via
  the new verb. Until the commit step runs, the canonical .validate.md
  is either the prior run or absent — never partially observable.

  Also supports an explicit --from/--to mode for atomic renames where
  the spec/kind convention doesn't apply.

  16 new tests in tests/cli/artifact.test.mjs cover: usage errors,
  containment violations, missing/empty source rejection, both spec/kind
  and from/to surfaces, happy-path rename, existing-destination overwrite,
  and the review kind.

epic-85 / issue-500 — check-12 prefix disambiguation
  Added a historical-context note to configurable-checks.spec.md's
  Canonical Check IDs section explaining that the duplicate `check-12-`
  prefix (`-lifecycle-reconciliation` AND `-heuristic-extraction`) was
  intentional — the legacy registry never assigned a Check 13 numeric
  ID, since "Check 13" was prose only in skills/validate/SKILL.md.
  Both IDs were dropped by check-set-restructure.spec.md, but the
  note is retained for anyone reading the superseded spec, the
  REMOVED_CHECK_ID diagnostics, or historic .validate.md reports.
