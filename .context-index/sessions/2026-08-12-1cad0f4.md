## Intent

feat(issues): bind issues to branch/PR and add atomic claim

Adds four issue-scoped fields to the board — branch, pr, owner, claimed_at —
and an `adev issues claim` / `release` pair built on the existing CAS
discipline, so a second agent cannot start work a live owner already holds.

Both issues are done as ONE schema change: each new field has to be threaded
through the same six files, and `validateIssue` returns a FIXED WHITELIST
object, so a field missing from that return literal is silently dropped
rather than rejected — create() reports success and persists nothing.
Threading sites: the Issue typedef, the type-check block, the whitelist
return literal, both beads metadata-map sites (create + list) plus beads
update(), the markdown parser's canonical row (now 18 columns, with the
14/13/12 legacy layouts retained), and the markdown renderer.

Claim semantics:
  - `claim <id> --owner <name> [--branch <b>] [--pr <p>]` sets owner +
    claimed_at atomically; refuses a DIFFERENT owner with
    ISSUE_ALREADY_CLAIMED (exit 2).
  - Re-claiming as the same owner is idempotent and preserves the original
    claimed_at; a fully redundant re-claim does not write at all.
  - `release <id> --owner <name> [--force]` clears owner/claimed_at, keeps
    branch/pr as a record of where the work went.
  - The precondition is `requireClaimable`, a pure check modelled on
    lifecycle-state.mjs::requireGate, evaluated INSIDE _withCas so the
    check-and-set is atomic against concurrent writers.
  - No lease expiry/TTL — deliberately separate work. A claim is live until
    it is released.

Not a board-granularity violation: planTask is rejected from the board
because it is SUB-ISSUE state (1:many, one advance per execution step).
These four are 1:1 with the issue, spec_ref is the standing precedent for a
ref field on the board, lib/lifecycle-state.mjs is spec-scoped rather than
issue-scoped and has no branch/PR/owner event kind, and the board is the only
worktree-spanning store. The rationale is recorded next to
_validateBoardGranularity, where the objection will be raised.
