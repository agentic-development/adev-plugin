## Intent

feat(lifecycle): enforce the issue claim in implement and debug preflight

Closes the behavioural half of issue-608. The claim mechanism itself landed
in da45a279 (adev issues claim/release, owner/claimed_at, the CAS-atomic
requireClaimable precondition) — but nothing called it, so the board carried
the "someone is already on this" signal and no skill read it.

That is not hypothetical. Two agents independently diagnosed and fixed the
same p0 command-injection bug an hour apart, opening duplicate PRs #214 and
#215. issue-582 was already in_progress the entire time.

/adev:implement claims the plan's epic in Step 1 before dispatching any task
and releases it in Step 4. /adev:debug gains a --issue argument and a new
Phase 1.6, placed after reproduction and before investigation — reproducing
is cheap, investigating is where the hour goes.

Exit codes are the gate, on the same discipline as requireGate:
  2  refused (held by another owner, or closed) — halt, report the holder,
     and never take over autonomously; takeover is a user decision
  1  usage error or CLAIM_UNSUPPORTED_BACKEND — warn and continue, since a
     backend that cannot check-and-set cannot offer the guarantee and
     blocking on it would train bypassing
  0  claim held; re-claiming as the same owner is idempotent, so a resumed
     session is not penalised

lifecycle-integration.spec.md goes to revision 2 with behaviors 12-17 and
adds skills/debug/SKILL.md to its source manifest. The claim primitive stays
specified by backend-migration.spec.md — this spec only owns the obligation
to call it. Its pre-existing drift (behaviors 2 and 5 predate the
board-granularity invariant) is untouched and still flagged.

The new tests pin the halt semantics rather than the wording: the regression
worth catching is a future edit softening "STOP" into "consider stopping",
which no runtime test would see.
