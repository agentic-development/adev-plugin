## Intent

fix(governance): actually apply the resolved reviewer model tier

adev-plugin-reviewer-tier-not-applied-wohx. The defect was deeper than the
issue stated: it was not only that the skill's dispatch list failed to name
`modelId`, but that the value was never computed at all.

lib/governance/dispatch-shape.mjs and both harness adapters already thread a
`modelIdFromTier` callback through to `dispatch.modelId` — and NO production
caller ever supplied it. Only tests/profiles/adapters.test.mjs did. Nothing in
lib/ or cli/ read `model_tiers` or `platform-context.yaml` at all, so the tier
map was documentation that nothing consumed, and modelId was always undefined.

  - lib/model-tiers.mjs reads .context-index/platform-context.yaml:model_tiers
    (absent file or key is not an error — callers fall back to the session model,
    which is the pre-existing behaviour) and resolves a reviewer's profile tier
    to a concrete id. It strips the trailing `# comment` prose the shipped file
    carries on each value.
  - `adev governance reviewers --json` now emits `model_tiers` plus `model_tier`
    and `model` per reviewer, so the orchestrator reads the resolved value from
    the envelope it already loads in Step 3 — no new verb, no inline Node.
  - Step 4's dispatch list names `model` explicitly and states that passing it is
    not optional, because the failure is silent: an unpassed tier changes nothing
    observable, the review still completes, just on the wrong model.
