## Intent

feat(pr-review-brief): spec pr-body-composition

Covers three of the charter's four must-have capabilities in one spec:
provenance rollup by spec, attention map from routing scores, and
verification summary. Grouped by cohesion — all three are sections of one
generated artifact governed by the same marker and determinism invariants,
and cannot be specified independently without restating those invariants
three times.

9 behaviors, 7 error cases, 8 tasks, 10 acceptance criteria.

Two constraints carried from the charter into testable form:

- A task present in the diff but absent from routing.json renders UNKNOWN
  and sorts ABOVE auto-agent rows. ~20 legacy plans still lack routing
  sidecars (issue-528), so the common case must not read as "nothing risky
  here". Empty sections render an explicit gap line rather than vanishing.
- Trailer values containing ] , newline, or shell metacharacters are
  escaped on output and never evaluated (issue-582 found the same values
  reaching a node -e context and unquoted YAML frontmatter).

The verb is read-only: no lifecycle writes, no network, no forge CLI. Exit
0 whenever HEAD and base resolve, regardless of which optional inputs were
missing — absent routing sidecars and validate reports are normal input
states, not errors.

Frontmatter is emitted before the H1, following shipped convention and
epic-104 rather than the legacy template shape (H1 first), which trips the
parser issue fixed in #208.

Charter Capability Map updated: the three covered capabilities move to
Status "specified". Bound to issue-612 on the board.
