## Intent

fix(frontmatter): read frontmatter behind multi-line comment preambles

Three near-duplicate preamble scanners each skipped blank lines, `#` lines
and lines starting with `<!--`, but never tracked an *unclosed* comment. A
multi-line HTML comment's continuation line is non-blank, has no leading
`#` and no leading `<!--`, so the scan treated it as body content and gave
up before reaching the fence — returning `{}`.

129 of this repo's 254 .spec.md files open with an H1 + multi-line comment
preamble and were mis-read by all of them. `adev specify amend` failed loud
(INVALID_AMENDMENT_BASE on a spec that plainly carries `revision:`), but
amendment-graph failed *silent*: it simply reported no `amends:`
relationship, and via lib/cli/test-policy.mjs spec-level `test_strategy` /
`test_depth` silently fell back to defaults.

A second, independent defect compounded it: the scan capped at 10 lines,
while 7 files carry a REVISION HISTORY comment that pushes the fence to
line 11 or 15. Comment tracking alone would still have missed those.

Consolidates all three into lib/frontmatter.mjs, which tracks comment
state, terminates at the first line of real content, and bounds the walk at
MAX_PREAMBLE_LINES.

Two hazards surfaced while delegating:

- specify-revise's rewriteFrontmatter splices lines[0..openIdx] +
  frontmatter + lines[closeIdx..] to carry the preamble through a rewrite
  byte-identically. It depended on bookkeeping the naive shared signature
  dropped, which would have corrupted spec rewrites with no error. The
  shared parser now returns lines/openIdx/closeIdx for exactly this.
- `export { x } from './y'` creates no local binding, and
  amendment-graph.mjs uses the function internally; it needs both an import
  and an export.

Tests: 11 for the shared reader (incl. a `---` inside a comment not being
mistaken for the fence) and 2 revise regressions covering the preamble
round-trip. The pre-existing revise fixtures only had an H1 + blank line,
which is why this went uncaught. Both regressions verified non-vacuous
against the old algorithm.

source-manifest of spec-amendment-artifacts.spec.md is left untouched:
per ADR-0011 the re-stamp is /adev:validate's on operator opt-in, not a
hand edit. lib/frontmatter.mjs still needs adding to a manifest files list.
