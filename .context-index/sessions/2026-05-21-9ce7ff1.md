## Intent

fix(session-awareness): correct token-pricing table + add Opus 4.7

The price table in lib/token-pricing.mjs had three bugs that caused
cost_usd to be wrong (or null) across the board. Discovered while
debugging why /adev:retro session-activity reported cost_usd: null
for every Opus 4.7 session.

Bugs:

1. Missing `claude-opus-4-7` entry — Opus 4.7 launched after the
   token-cost-logging spec was validated and the table was never
   updated. getRate("claude-opus-4-7") returned null, computeCost()
   stamped cost_usd: null on every session-tracking.jsonl line.

2. `claude-opus-4-6` was priced at $15/$75/$1.50/$18.75 per MTok —
   the legacy Opus 4 / 4.1 rate sheet. Anthropic's current price
   table puts Opus 4.5/4.6/4.7 at $5/$25/$0.50/$6.25 (5m cache
   writes). Past cost figures for Opus 4.6 sessions were 3x too
   high.

3. `claude-haiku-4-5-20251001` was priced at $0.80/$4/$0.08/$1 —
   the legacy Haiku 3.5 rate sheet. Current Haiku 4.5 rate sheet
   is $1/$5/$0.10/$1.25. Past Haiku cost figures were ~25% too
   low.

Source: https://platform.claude.com/docs/en/about-claude/pricing

Schema mapping vs the published table is documented inline:
  input          → "Base Input Tokens"
  output         → "Output Tokens"
  cacheRead      → "Cache Hits & Refreshes"
  cacheCreation  → "5m Cache Writes" (default cache_control TTL).
                   1h writes (2x base input) are not modeled in the
                   per-token cost path.

Tests in tests/lib/token-pricing.test.mjs are updated to match the
real rates and now include a regression guard on opus-4-7 to catch
future regressions to the legacy Opus 4 / 4.1 rate sheet. 19/19 tests
pass.

Live confirmation: with the new table loaded, /adev:retro
session-activity entries now carry real cost_usd values
(e.g. $0.357 for a 690k cache-read tool call) instead of null.

**Caveat:** historical .session-tracking.jsonl entries with
cost_usd values recorded against the buggy table are inflated for
Opus 4.6 (~3x too high) and deflated for Haiku 4.5 (~25% too low).
Going-forward writes are accurate. Consumers that aggregate
historical cost should treat pre-2026-05-21 values as estimates.
