## Intent

fix(cli): correct install/uninstall scope, cache pruning, and multi-profile handling

Three related defects in the Claude Code install/uninstall path, all
rooted in the same registry-row model:

- updateRegistry() overwrote the whole plugins[key] array with no
  projectPath, so a project-scope install in one repo silently
  dropped the row a project-scope install in another repo had
  written (GH #378). Now upserts by (scope, projectPath).

- cleanOldVersions()/uninstall() treated the plugin cache as owned by
  a single scope: installing or uninstalling for one project deleted
  cached versions another scope/project's row (same claudeHome) still
  pointed at (adev-plugin-cli-tag-scope-collision). Pruning is now
  driven by which versions any surviving registry row still names.

- getClaudeHome() ignored CLAUDE_CONFIG_DIR, always writing to
  [REDACTED:path] even when the invoking shell's Claude Code session reads
  from a different profile. install/uninstall now honor it and, when
  a machine has more than one discoverable config dir, prompt for
  which to target.

Also fixes a CLAUDE_CONFIG_DIR leak in tests/cli-e2e.test.mjs: the
spawned-CLI test helper forwarded the ambient env verbatim, so a
developer or CI profile with CLAUDE_CONFIG_DIR set (now meaningful to
getClaudeHome()) redirected the E2E install assertions onto a real
config dir instead of the test's tempdir.
