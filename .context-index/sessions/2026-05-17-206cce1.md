## Intent

feat(agent-reliable-state-artifacts)!: CAS over atomic rename for JSON issue board

Adds optimistic compare-and-swap (CAS) to lib/issues/json-adapter.mjs so
concurrent mutators on a shared tasks.json cannot silently overwrite each
other. Resolves issue-459.

- Schema validation accepts an optional non-negative integer `seq` field
  (Task 1). Out-of-range values throw INVALID_BOARD_SEQ; error messages
  do not echo the offending value (SEC-1 sanitization).
- New _readWithSeq() returns { board, seq } for mutator paths; legacy
  documents lacking `seq` are treated as seq:0 (Task 2). _read() unchanged
  for read-only callers — they pay no CAS overhead.
- _write(data, expectedSeq) re-reads tasks.json immediately before
  renameSync, compares disk seq to expectedSeq, throws
  STALE_BOARD_WRITE_RETRY on mismatch (Task 3). Successful CAS write
  stamps seq=expectedSeq+1. expectedSeq=null bypasses CAS for init path.
- All six mutators (create, update, close, addDependency, createEpic,
  updateEpic) wrap their RMW cycle in bounded CAS retry via _withCas()
  helper (Task 4). MAX_CAS_RETRIES=3 default; overridable via
  manifest.tasks.cas_max_retries. After budget exhausted: throws
  STALE_BOARD_WRITE with op name, captured seq, current seq, retry count
  (no filesystem paths or document contents).

Cross-spec amendment to json-issue-board-adapter.spec.md (top-level-key
preservation rule for seq) lands in plan-task 10.

BREAKING CHANGE: the on-disk tasks.json document now carries a `seq` field
when written by this adapter. Legacy tasks.json files without seq are
upgraded transparently on first mutation; no adev migrate invocation
needed. External tooling that reconstructs tasks.json from a parsed
shape must preserve the seq field (drop-unknown-top-level-keys rule
has a documented exception).
