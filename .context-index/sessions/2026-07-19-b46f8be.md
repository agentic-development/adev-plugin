## Intent

fix(skills): pin run_in_background:false on all Agent dispatches

The harness now backgrounds Agent-tool dispatches by default: the call
returns a task ID immediately and the caller is only re-invoked by a
completion notification. That notification path works only at the top
level of a session — nested subagent contexts are never re-invoked, so
backgrounded nested dispatches stall. Field-observed as /adev:build
step subagents (implement, review-specs) that auto-background and never
return a STEP_RESULT.

Pin run_in_background:false on every Agent dispatch in build (all six
step dispatches + dispatch-loop prose), implement (per-task implementer
and all reviewer/verifier dispatches), and review-specs (parallel
reviewers, still concurrent via single-message dispatch). Amend
adev-build-skill.spec.md Behavior 13 to make synchronous dispatch part
of the behavioral contract. Provider mirrors regenerated via
scripts/sync-provider-skills.mjs.

Longer-term background-native orchestrator design tracked as issue-549.
