## Intent

docs(governance): revise to rev 3 — close the rev-2 blockers at their root

Rev 2 addressed all five rev-1 blockers and drew five new ones; no ID
repeated, so the convergence detector returned CONTINUE. Three of the five
shared one root cause.

The un-materialized predicate was keyed on "no marker AND empty entry list
AND defaults exist". Every conjunct was wrong. Emptiness left the partially
populated case open — registries compose additively, so a project with one
hand-added reviewer plus three bundled ones is not empty and would have lost
the three bundled reviewers, security-reviewer among them, exactly the silent
loss Invariant 2 forbids. One entry defeated the guard, and hand-adding one
reviewer is the workflow review.yaml's own header documents. "Defaults exist"
was undecidable: it asks about the merged set, which the same step removes.
Rev 3 makes `materialized_at` the sole discriminator, decidable from the
project file alone, and refuses extension install into an unmarked registry
so install cannot pre-empt materialization.

The protected-key list for the collision fill-gap loop omitted the fields
that execute. gates.yaml entries carry `command:`, which reaches spawnSync,
so an extension colliding on a gate id whose entry has no command could
inject a shell command into a project-owned entry — arbitrary execution at
every post-task trigger, permanent because the entry reads as project
authored. Rather than extend the list, rev 3 removes fill-gap merging: a
colliding entry is skipped and the existing entry is left byte-identical.

The regex time budget was unimplementable as written. A synchronous
RegExp.exec cannot be interrupted mid-backtrack, while the Constitution
Reference asserted evaluation "needs nothing beyond RegExp". Rev 3 names the
mechanism — node:worker_threads with terminate() on expiry, 250 ms per rule
per file, 1 MB input cap — and corrects the constitution claim.
