## Intent

feat(cli-driver-surface): PR 4 — extract Step 0a requireGate (all lifecycle skills)

Replaces inline `requireGate(state, "<step>", { mode })` JavaScript
pseudocode in plan, review-specs, implement, validate, and build
SKILL.md files with `adev gate require --skill <skill> --spec <p>` CLI
invocations. The helper lib/cli/gate.mjs is unchanged from
driver-substrate — PR 4 is pure call-site migration per spec Behavior 9
(canonical-verb reuse). `skills/specify/SKILL.md` has no Step 0a gate
(it's the first lifecycle step; correctly absent from gate.mjs's
SKILL_STEP_MAP).

This collapses the two-fence pattern PR 3 introduced in Step 0a
(`javascript` requireGate + `bash` adev report) back to a single bash
block per skill. The very first action of every lifecycle skill is now
`adev gate require` instead of inline JS.

The FORBIDDEN-regex footprint is unchanged from PR 3 (15 skills,
50 blocks) because the regex matches `node -e` / `node --input-type`
patterns, not JS-fenced requireGate blocks. PR 4's value-delivered is
grep-visibility and prose/code separation, not a regex-count drop.
