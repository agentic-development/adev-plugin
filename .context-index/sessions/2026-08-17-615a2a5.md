## Intent

fix(specify): open and close specify on an amendment's own log

`adev specify amend` wrote `spec_amended` to the BASE spec's log and nothing
else, so the amendment never got a lifecycle log of its own. `currentState`
projected its `specify` step as `{status: "missing"}`, and
`adev gate require --skill review-specs` exited 2 under the default strict
mode — `gate_mode` is commented out in manifest.yaml, so strict applies.

Every amendment was therefore unreviewable, which contradicts the scaffold
text the verb itself writes: "The base spec is immutable; this artifact
carries the delta and is reviewed, planned, and validated on its own
lifecycle." An artifact cannot be reviewed on a lifecycle nothing opens.

Reviewing against the base path is not the alternative: /adev:review-specs
Step 7 rewrites the `status:` frontmatter of whatever `--spec` it is handed,
so that would flip the immutable validated base to review-passed or
review-blocked — breaking the exact immutability the amend workflow exists to
protect.

`amendSpec` now calls `reportStep` twice on the amendment's own log, after the
atomic write: `started`, then `completed` with verdict `PASS`. Both are
required, in that order:

- A terminal with no matching `started` is precisely what ORPHAN_STEP_TERMINAL
  will reject once lifecycle-event-log rev-5 BEH-7 lands, so emitting only
  `completed` would be rejected by a sibling change already in flight.
- A terminal without an explicit string verdict is overwritten by the verdict
  synthesized from actor reports, so the `PASS` is load-bearing.

The base log deliberately gains no `specify` events — the base was not
re-specified. A test asserts that separation in both directions, so a future
change cannot satisfy the gate by polluting the base log instead.

Verified end to end through the real CLI on a live amendment:
`gate require` exit 2 before, exit 0 after.

Skill prose corrected in three mirrored copies (skills/, providers/codex,
providers/opencode). The "Every mode" list previously omitted Amend; it now
states that Amend is NOT exempt — the verb emits the pair, so the skill must
not emit it again or the step opens twice.

The fix is forward-only. The rev-5 amendment committed in 2843d516 predates it
and needed the pair backfilled by hand; its log is included here. No other
amendment exists in the repo.

Suite: 7077/7035, +3 tests +3 passes over the 7074/7032 baseline. The 10
failures are unchanged tests/repomap ENOENT on node_modules tree-sitter wasm.

`spec-behavior-ids.spec.md` gained `drift_detected: true` because
skills/specify/SKILL.md is in its source-manifest — the write-time hook firing
correctly. Clearing it is /adev:validate's on operator opt-in per ADR-0011.
