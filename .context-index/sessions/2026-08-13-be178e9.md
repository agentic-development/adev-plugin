## Intent

fix(maintenance): mask template literals before Class A extraction

Third false-positive class, found by dogfooding the pass against this repo after
wiring: the engine's own test tripped DEAD_TEST_REFERENCE on lib/foo.mjs, a module
named only inside a backtick fixture string.

A test that BUILDS a source file as a string is not importing the module that string
names. Template-literal contents are fixture data, not code. Masking them (preserving
line structure) removes the finding; real imports never appear inside a template
literal, so nothing legitimate is lost.

Spec rev 4 records the rule and the observation.
