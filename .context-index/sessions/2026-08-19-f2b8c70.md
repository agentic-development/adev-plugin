## Intent

refactor(skills): split the five largest SKILL.md bodies into references/

Progressive disclosure per the Agent Skills spec: material an agent needs
only sometimes moves into references/ and is loaded on demand, keeping the
always-read body small. No prose was deleted -- every instruction still
ships, one file away, and is still asserted by the same tests.

  hygiene    65350 -> 12135   23 audit passes -> references/audit-passes/,
                              body keeps a routing table + --check slugs
  build      65345 -> ~21500  pipeline steps, delegation, dry-run, single-spec
  implement  64916 -> ~21600  per-task loop and step bodies
  specify    64119 -> ~15200  seven mode bodies -> references/modes/
  validate   60062 -> ~22500  per-check orchestration, report format

hygiene and build were 186 and 191 bytes under the hard 65,536-byte cap in
lib/providers/copilot/skill-validator.mjs, where overflow throws
INVALID_SKILL_FRONTMATTER and takes down every Copilot adapter path.

Rules that govern a whole invocation stay in the body, not a companion:
the Load Skill Extensions block (build, validate) and the synchronous-
dispatch / never-end-your-turn rules (build, implement, validate) were
carried out by the split and are restored, with tests still pinning them.

Tests: readSkillSurface()/readSkillSurfaceAt() in tests/helpers.mjs read
SKILL.md plus its references/ companions, so content assertions follow the
prose instead of silently ceasing to test it. Assertions that are about
ORDERING or a specific section read that one companion directly -- sibling
mode files number their own steps, so offsets across the concatenation
would compare headings from different modes.
