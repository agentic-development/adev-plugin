## Intent

docs(review): widen rev-5 review-gate amendment to rev 5 — address four rev-4 blockers

Operator chose to widen the amendment rather than narrow or split it, so the
machinery the contract depends on is now specified here rather than assumed.

SEC-1 + SA-3 (both on BEH-1b, one root cause): rev 4 required JSON.stringify
over "the PARSED value" but named no parser, and the repo has none capable —
lib/frontmatter.mjs captures indent-0 scalars only and its docblock says nested
keys and list items are ignored. With 221 corpus specs carrying nested
frontmatter, a parsed-value digest would leave all of it unattested: the same
CWE-345 hole one nesting level down. Inventing a fourth in-tree parser (three
already diverge: test-strategies/profiles, meta-tools, session-summary) would
reproduce the CWE-436 conflict BEH-1b exists to close.

Resolved by taking the reviewer's own recommendation (2): the attested region is
now built by LINE-ANCHORED REMOVAL from raw bytes — drop each denylisted key's
indent-0 line plus its indented continuations, retain everything else verbatim.
Removal is line-anchored rather than value-derived, so nested and multi-line
content is attested byte-for-byte with no parser in the retained path and no
aliasing. New BEH-1c fails closed with SPEC_SHA_UNCANONICAL on duplicate keys or
a malformed delimiter rather than attesting a partial view. parseFrontmatter is
named as the sole helper, used only to LOCATE key lines, never to read values.

SA-2: byRevision[N].specSha rested on an unstamped field. New BEH-3c makes
revision stamping a deliverable — reportReviewer stamps it, `adev report --type
reviewer` gains --revision — and states plainly that this widens scope into
lib/cli/report.mjs, co-owned by explicit-governance-registries and
measurement-integrity, which must be updated in the same change.

SA-1: BEH-3a never defined the EMPTY window. `adev specify revise` rewrites spec
bytes and emits spec_revised without reopening the review step, so review PASS ->
revise -> plan left zero reports in the window, projected specSha absent, and
took BEH-5's non-blocking path while the stale PASS still opened the gate. New
BEH-3d projects "unreviewed-since-revision" and blocks under strict, explicitly
distinct from the never-stamped case BEH-5 is reserved for.

Behaviors 14 -> 17, acceptance criteria 24 -> 28, two new error-case rows.
Behavior IDs reordered into sequence. rev 4 -> 5. adev diagnose clean.
