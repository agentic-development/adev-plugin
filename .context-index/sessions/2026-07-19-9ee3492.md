## Intent

ci: add release/next pre-release channel wiring

Wire a "next" pre-release channel into the release pipeline:

- release.yml triggers on pushes to release/next and publishes that
  branch to the npm "next" dist-tag (main -> latest, release/0.x ->
  legacy, unchanged).
- Pass target-branch to release-please-action: without it, the action
  opens release PRs against the repo default branch (main) even when
  triggered from release/0.x or release/next, so non-main channels
  could never release correctly.
- Document the @next install path in docs/installation.md.

The prerelease versioning config (prerelease: true, prerelease-type:
next in release-please-config.json) deliberately does NOT land on main
- it lives only on the long-lived release/next branch, otherwise every
main release would be cut as a prerelease and published to "latest".

Supersedes the version-bump approach on claude/open-prs-work-summary-mq55zs:
manual bumps to 0.28.0-next.0 diverge from .release-please-manifest.json
bookkeeping; release-please owns all version bumps (see PR #97 precedent).
