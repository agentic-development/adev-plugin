## Intent

docs(test-strategies): test-depth-policy rev 5 — enforce the floor end-to-end

Addresses the round-4 security findings (SEC-6 through SEC-12).

SEC-6 (blocker): the floor had no effect on any suite. `resolve` computed
a depth, passed it to a subagent as a prompt input, and `assert-assigned`
verified only that an event existed. With `per-behavior` as the shipped
default, suite reuse is the common path, so a sensitive-path task floored
to `thorough` would routinely extend a `minimal` suite. Two fixes: a task
whose depth exceeds an existing suite's now gets "extend and raise", and
`assert-assigned` gains a conformance leg reading `assigned_depth` and
covered case classes from the already-hashed Handoff Block.

SEC-11: declared paths are author-supplied and plan immutability is only
enforced post-hoc, so deleting a path before `resolve` removed the floor.
`assert-assigned` now re-evaluates the floor legs against the files the
task actually touched.

Also: Capability no longer claims the whole floor is un-narrowable (only
the sensitive-path leg is monotone); sensitive-path matching is pinned to
repo-relative POSIX via the existing `matchGlob`, with directory and file
forms so `src/auth.ts` and `services/api/.env.production` both floor; the
self-hosting overlay is named; `--task-id` grammar is pinned inline; and
`show`/`explain` are barred from echoing paths.

Known Limitations rewritten to reflect what is now enforced. The three
non-security blockers from round 4 (SA-20, SA-21, CON-25) remain open.
