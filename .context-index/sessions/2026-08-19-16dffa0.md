## Intent

fix(governance): support dispatch.triggered for bundled/domain reviewer entries

`termination-reviewer`'s spec-mandated dispatch shape (`dispatch: {
triggered: { keywords: [...], min_score: N } }`) is two levels deep with an
array leaf, which lib/extensions/governance-splice.mjs's emitter and
lib/extensions/governance-values.mjs's value-safety checks only supported to
one level with scalar leaves. `adev governance materialize --registry review`
failed for every software-domain project as a result.

Adds assertValidDispatchTriggered (governance-values.mjs) as a narrowly-scoped
second shape — analogous to the existing assertPackageKeys precedent in
governance-registry.mjs, but for BUNDLED/domain-sourced content, not
extension-installed content. The separate, harder extension-trust boundary in
governance-registry.mjs (VALID_DISPATCH, Decision B) is untouched and stays
closed to always/never. Round-trip safety through the real emitter and the
real lib/profiles/yaml.mjs parser is covered by new tests, including the
documented colon+whitespace and flow-structure attack classes.

Also fixes two disabled_reason strings in the software domain's retargeted
reviewers.yaml that independently tripped the scalar-safety refusal (a
colon+space and embedded quotes/commas), and updates
tests/domains/backward-compat.test.mjs's stale 3-reviewer assertion to pin
against the current 7-entry (5 active + 2 disabled) panel now that the
reviewer-domain-fit retarget intentionally ends that file's mirroring of the
old templates/review-specs/defaults.yaml bundle.
