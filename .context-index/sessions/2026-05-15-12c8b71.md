## Intent

docs(build): correct gate-mapping comment to match lib contract

The Per-step gate mapping comment told operators to "use the PRIOR
step's name" as the second arg to requireGate, but the lib treats
that arg as the STEP ABOUT TO BEGIN and resolves the prior internally.
Following the old comment would call requireGate(state, "implement", ...)
before validate — which checks route (implement's prior), not implement
itself. This is the exact bug that blocked validate dispatch during
the lifecycle-artifacts charter build (fixed in skills/validate/SKILL.md
at commit f635b6a).

Rewrote the mapping table to show each call site as
`before X → requireGate(state, "X", { mode })` with an inline note
that the lib resolves the prior. Added a note about route being in
OPTIONAL_GATE_STEPS so readers understand why implement's gate skips
straight to plan.
