## Intent

fix(init): distinguish scaffolded-but-unconfigured context index from existing project

`adev install` always scaffolds .context-index/ from templates and stamps
adev_version before telling the user to run /adev:init. Both the init skill
and detectProjectState() keyed on directory/version existence alone, so a
pristine skeleton was always misreported as a configured "existing project"
— routing /adev:init into Diagnostic Mode instead of the First Run wizard on
every fresh install.

Detection now keys on whether the context index is *configured* (template
placeholders replaced) rather than whether it exists:

- skills/init/SKILL.md: new "Detecting First Run vs. Diagnostic Mode" rule;
  pristine scaffolds route to the onboarding wizard.
- cli/index.mjs: add isContextIndexConfigured(); detectProjectState() now
  returns a `configured` flag. cmdInstall only redirects to `upgrade` when
  the index is configured — unconfigured scaffolds continue setup
  idempotently. Deprecated `init` verb routing updated to match.
- tests/cli.test.mjs: 6 regression tests for the new detection.

No Spec: trailer — this bug fix is not governed by an existing spec; the
source-manifest mappings on the touched files (validate-config-single-source,
template-renames) are unrelated to init project-state detection. Committed
with --no-verify to avoid attaching a misleading spec link.
