## Intent

feat(issues): mint merge-safe board IDs — closes issue-613 via option (a)

`max(existing) + 1` is safe against concurrent writers of one file (the CAS
lock) and across worktrees (resolveStorageRoot), and still wrong across git
BRANCHES. Two sessions off one baseline each computed 589, each was valid
locally, and the collision only surfaced at merge — two different issue-589s,
plus an epic-108 referenced on main that existed on no board.

Flat ids are now `<prefix>-<6 base36>` from crypto.randomBytes, re-rolled
against the current board and bounded at 8 attempts (ID_MINT_EXHAUSTED rather
than an infinite loop on a degenerate generator).

Randomness, not a wider counter, is the actual fix: it removes the need to
consult shared state to know an id is unique, which is exactly what a branch
cannot consult. beads reached the same answer independently (`bt-i6s`), and
on that backend this composes with br's uniqueness constraint on external_ref
— a residual collision becomes a rejected write, not a silent duplicate.

EXISTING SEQUENTIAL IDS ARE NEVER REWRITTEN. ~600 of them are quoted in merged
commits, specs, and prose. LEGACY_RE widened so parseId recognizes both shapes
as `legacy: true` — deliberately the same arm, because every parseId caller
branches on `.legacy` and never on the suffix. Had the new shape returned null
instead, lib/retro/issue-id-validation.mjs would have classified real ids as
"unrecognized" and refused the board lookup.

Also widened `_isLegacyEpic` in the beads adapter, which gated on
/^epic-\d+$/: left alone it would have created new epics and then silently
omitted every one of them from listEpics().

The discriminating test is a real two-branch concurrent mint plus merge, not a
charset check on the generator — a charset test passes against the old
algorithm too. Verified non-vacuous: it reproduces the original collision when
_nextIssueId is reverted to max+1.

Scope and costs, stated rather than buried:
- Tiered dotted ids (e1.f2.t3) still use nextChildId's max+1 and remain
  branch-unsafe. No board here uses them (0 of 295), so redesigning that model
  speculatively was not worth it. Recorded in the spec.
- Ids no longer imply creation order; render-markdown's lexicographic grouping
  is now arbitrary. Chronology comes from `created`.
- Option (b) — `issues renumber` plus a CI collision check — is deliberately
  NOT built. It detects a class that (a) prevents.

Several tests asserted `issue-1`/`epic-1` literals as a side effect of testing
CRUD, CAS retry, and orphan-lock recovery. Each now captures the returned id
or matches the shape; none of their actual subjects changed.
