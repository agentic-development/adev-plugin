## Intent

feat(review): warn TARGET_SPEC_OVERSIZE without truncating the target spec

`specBlock` in `dispatch-shape.mjs` retains ownership of target-spec inlining;
`renderPack` never inlined it and must not start — `defaults.yaml` gives
`review-base`'s sibling-specs include `exclude: ["<target-spec>"]`, so adding an
inlining path in the pack would ship the spec twice per prompt.

BEH-12's exemption from `max_file_bytes` / `max_total_bytes` is therefore
implemented as a dispatch-assembly guarantee per SA-1's second recommendation,
not as a new mechanism: the spec body never enters `renderPack`'s byte
accounting, so there is no truncation path, no per-file marker and no
`role="truncation-notice"` for it. The one observable addition is the advisory
`TARGET_SPEC_OVERSIZE` warning, emitted once per `buildReviewerDispatches` call
at the shared `specBlock` site, naming the path, the actual byte size and the
resolved cap.

`renderPack` now returns the resolved `budgets` and `delivery` on every path,
including the early-error bails, so the comparison reads resolved (possibly
inherited) budgets and no caller can dereference `undefined.maxTotalBytes`.
`delivery` is `null` — not `"inline"` — when `resolveExtends` failed, because an
unresolved pack has no determined mode.

Spec-text re-anchoring for BEH-12 is deferred to `adev-plugin-j7pq.7`.
