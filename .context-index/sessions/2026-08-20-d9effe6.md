## Intent

fix(specify): move partial_schema marker into frontmatter, not an HTML comment above it

skills/specify/SKILL.md Step 5 prescribed writing the partial_schema marker
as an HTML comment above the frontmatter delimiter. adev/frontmatter-present
(severity: error) requires the first non-blank line of a .spec.md to be ---,
so every spec authored per the skill's own instruction was born violating an
error-severity diagnostic, and the marker survives the atomic rename into the
final artifact untouched.

incremental-artifact-writes.spec.md SA-6 only requires the marker to be "in
the first authored chunk" — the HTML-comment-above-frontmatter placement was
over-specified by the skill, not mandated by the spec. Moves the marker into
a partial_schema: spec@1 frontmatter key instead, which readSchemaMarker
(lib/cli/partial.mjs) still matches unchanged since it scans the first 4 KB
for the token regardless of surrounding syntax.

Backfills all 14 live cross-cutting and feature specs that were authored
under the old instruction (7 originally in this fix's scope, plus 7 more
discovered on reconciliation with main that carry the identical defect) so
the new "every committed .spec.md satisfies adev/frontmatter-present" guard
test passes against the full corpus, not just the specs this fix touched
directly.
