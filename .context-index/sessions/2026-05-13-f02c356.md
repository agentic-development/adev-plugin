## Intent

feat(agent-reliable-state-artifacts): test migration — schema-version surface and legacy-format guards

Replaces the legacy parser-variant test idioms (12/13/14-column branches in
tests/lib/issues/markdown-parser.test.mjs) with schema-version-based tests
keyed off the JSON document's `version` field. The schema-version mechanism
is already implemented in JsonAdapter; this work adds the test coverage that
documents and protects it.

What changes:

- Export UNSUPPORTED_VERSION_FALLBACK from lib/issues/json-adapter.mjs so
  tests can assert the canonical SEC-4 fallback message verbatim.
- New tests/lib/issues/json-adapter.schema-version.test.mjs:
    - version: 2 happy path
    - version: 3 forward-compat: unknown fields on epics/issues survive
      round-trip; top-level unknown keys are dropped on write (documented
      contract gap per CON-1 in the review report)
    - version: 1 / version: 0 / non-numeric rejection with the canonical
      fallback message (no raw-value interpolation per SEC-4)
- Nest the three column-variant tests in tests/lib/issues/markdown-parser.test.mjs
  under a new `describe("legacy-read regression (markdown adapter sunset)")`
  block. Bodies unchanged. Block carries a sunset comment referencing the
  charter's markdown-adapter removal timeline (charter.md line 59).
- New tests/architectural-legacy-format-fixtures.test.mjs guards against
  regression: zero `\b1[234]-column\b` matches outside the sunset block, and
  zero legacy-storage-format assertions (.execution-state.md, milestones.yaml,
  pre-rename build-state/) under tests/lib/ outside allowed paths.
- New CON-3 read-tolerance test in tests/lib/issues/json-adapter.test.mjs
  for legacy issues carrying both planRef and planTask.

Follow-up obligations recorded in the plan, not in this commit:

1. Clarify the version: 3 top-level-key drop-on-write contract in
   json-issue-board-adapter.spec.md (CON-1).
2. Couple sunset-block removal to tasks.backend: "file" removal so the two
   land together (SA-5).

Validation gate currently fails on a pre-existing flaky perf test
(tests/lib/lifecycle-state-perf.test.mjs:123) which is unrelated to this
spec's source-manifest. All spec-introduced tests pass.
