## Behavioral Contract

This spec defines the read-only **markdown rendering layer** sitting on top of the authoritative JSON / JSONL state artifacts. It introduces two render functions and one aggregation helper, plus two CLI subcommands that surface them:

- **`lib/issues/render-markdown.mjs::renderTasksMd(board) → string`** — pure transformer that consumes the parsed `tasks.json` document (per the json-issue-board-adapter spec) and returns the markdown body for `.context-index/tasks/tasks.md`. The caller is responsible for writing the file via atomic temp-then-rename; the lib itself is I/O-free aside from the optional `writeTasksMd(projectRoot)` convenience that wraps the transformer with `JsonAdapter.list()` + atomic write.
- **`lib/lifecycle-state.mjs::renderMarkdown(state) → string`** — pure transformer (signature already established by the lifecycle-event-log spec as a stub) that consumes a `StateProjection` (the output of `currentState(projectRoot, specPath)`) and returns the markdown body for a per-spec lifecycle view. The full implementation lands in this spec; the lifecycle-event-log lib only committed to the stub signature.
- **`lib/lifecycle-state.mjs::listLifecycleStates(projectRoot) → { spec, slug, status, currentStep, updated }[]`** — globbing helper (signature already in the foundation spec) whose full implementation also lands here. Globs `<projectRoot>/.context-index/lifecycle-state/*.jsonl`, folds each via `currentState`, returns one record per file. No stored index; recomputed on every call.
- **`adev status --render`** CLI subcommand — regenerates `.context-index/tasks/tasks.md` from `tasks.json` AND every `.context-index/lifecycle-state/<slug>.md` from its sibling `<slug>.jsonl`. Operator-on-demand; never invoked autonomously by any lifecycle skill.
- **`adev status --pipeline`** CLI subcommand — aggregate read view. Calls `listLifecycleStates(projectRoot)` and prints a per-spec pipeline table to stdout (no file written). Operator-on-demand; safe to invoke at any time.

Every rendered markdown file carries a non-editable header (`<!-- DO NOT EDIT — generated by adev status --render from <source>. Edits will be lost on next regeneration. -->`) and is treated as a presentation artifact. The source of truth always remains the underlying JSON / JSONL. Editing the rendered file has no effect on the authoritative state; the next `adev status --render` invocation overwrites it. Every free-text field that flows through rendering (`notes` on reviewer / validator reports, `manual_override.reason`, issue `notes`, issue `next_action`, `step_failed.error`, plan-task `notes`) is **HTML- and markdown-escaped** before interpolation per the escaping rules below, addressing the deferred SEC-5 finding from the foundation reviews. The rendering layer never touches authoritative state, never invokes domain config (severity is read pre-stamped from each event), and never decides downstream actions — gates, plan generation, and validation all read from the JSON / JSONL directly, never from the rendered markdown.

## Naming Conventions (CON-1)

This spec preserves the field-name domains established by the four prior specs and introduces no new domains:

- **Issue / Epic fields:** consumed verbatim from `tasks.json` per `json-issue-board-adapter.spec.md` (mixed camelCase + snake_case Issue, snake_case Epic `plan_ref`). The renderer reads these as-is and emits them into table rows preserving the existing `tasks.md` column convention.
- **LifecycleEvent / StateProjection fields:** consumed verbatim from `lib/lifecycle-state.mjs::currentState` per `lifecycle-event-log.spec.md` (snake_case event-discriminator names; camelCase StateProjection keys `currentStep`, `currentTask`, `planTasks`, `startedAt`, `updatedAt`, `unknownEvents`).
- **Aggregate-record fields (camelCase):** the `listLifecycleStates` return value is `[{ spec, slug, status, currentStep, updated }]` per the charter's Interface Contracts. Preserved verbatim.
- **CLI flag names:** `--render` (boolean) and `--pipeline` (boolean). Both attach to the existing `adev status` subcommand. Boolean flags follow today's `--dry-run` precedent in `adev migrate` (one-shot-migration-tool spec) and `--provider <value>` in the CLI's broader flag-parsing conventions.
- **Generated-file basename:** `<slug>.md` for the rendered lifecycle view (sibling to `<slug>.jsonl`). The board's rendered file remains `tasks.md` (sibling to `tasks.json`). No new naming convention is introduced.

Implementers must NOT rename any field during rendering. The rendered output is a mechanical projection of the source data; renames would obscure the round-trip between authoritative state and human-readable view.

## Path Safety (SEC-1, SEC-4)

Every public function and CLI dispatch path enforces the path-containment contract established by the sibling specs:

1. **`projectRoot` normalization.** Every public function (`renderTasksMd`'s optional `writeTasksMd(projectRoot)` wrapper, `renderMarkdown(state)`, `listLifecycleStates(projectRoot)`, the CLI dispatcher) resolves `projectRoot` via `path.resolve()` at entry. The resolved path must contain `.context-index/manifest.yaml` (validated by `fs.existsSync`). If validation fails, throw `INVALID_PROJECT_ROOT` with the resolved path. Same contract as the four sibling-spec libs.
2. **Storage-root resolution for `tasks.md`.** `writeTasksMd(projectRoot)` resolves the storage root via `resolveStorageRoot(manifest, projectRoot)` — the **same helper** used by `lib/issues/json-adapter.mjs` and the rewritten `lib/milestones.mjs`. The output path is `<storageRoot>/.context-index/tasks/tasks.md`. Co-locates the rendered file with the authoritative `tasks.json` it derives from.
3. **Per-worktree resolution for lifecycle markdown.** `.context-index/lifecycle-state/<slug>.md` is per-worktree, matching the per-worktree resolution of the source `<slug>.jsonl` file. The CLI `--render` writes each lifecycle markdown file alongside its source JSONL.
4. **Read AND write path containment (realpath-prefix).** Every resolved read path (sources) AND every resolved write path (rendered targets) is asserted via `fs.realpathSync.native()` to live inside `<resolvedStorageRoot>/.context-index/` or `<projectRoot>/.context-index/` per the applicable rule. The check uses `realResolvedParent.startsWith(realScopeRoot + path.sep + '.context-index' + path.sep)` with the parent dir realpath'd when the target file does not yet exist. Any escape (crafted `tasks.db_path`, symlink under `.context-index/`, slug containing `..`) throws `INVALID_STORAGE_PATH` before any file is opened. Defeats CWE-22 path traversal and CWE-59 symlink following.
5. **Slug character allowlist for lifecycle render.** When iterating `lifecycle-state/*.jsonl` files for `--render`, each filename's stem (without `.jsonl`) MUST match `[a-z0-9._-]+`. Any filename failing this check is skipped with a `SKIPPED_INVALID_SLUG` advisory; rendering continues for the remaining files. Mirrors the live-write allowlist enforced by `lib/lifecycle-state.mjs` per the foundation spec.
6. **Source size cap for rendering.** Each `<slug>.jsonl` source file ≤ 50 MB (matching the lifecycle-event-log spec's `LOG_TOO_LARGE` defensive cap). If a source exceeds this cap, `renderMarkdown` is not invoked for that slug; instead an `OVERSIZED_LOG_SKIPPED` advisory is emitted naming the slug and the operator is referred to compaction (deferred capability). `tasks.json` source is bounded by `JsonAdapter._read` which inherits the JSON adapter's existing limits.
7. **Atomic-write parity.** Every rendered markdown file is written via the temp-then-rename pattern (`<finalPath>.<crypto.randomBytes(4).toString('hex')>.tmp`) mirroring `lib/build-state.mjs::atomicWriteJson`, including the best-effort `fs.unlinkSync` cleanup on the failure path. Readers concurrent with a write see either the prior content or the new content, never a partial render.

## HTML / Markdown Escaping Contract (SEC-5)

This spec resolves the SEC-5 finding deferred by both foundation specs (`lifecycle-event-log.spec.md` review rev 2 line: "not applicable until render spec lands"; the milestones-migration spec's SEC-5 future-rendering hand-off). Every free-text field that flows through rendering is escaped at the renderer boundary, **before interpolation** into markdown tokens.

### Escaped fields

The following fields are treated as untrusted operator/agent input and escaped on every render:

| Source | Field | Origin |
|---|---|---|
| `tasks.json` issue | `notes` | `JsonAdapter.create/update` payload |
| `tasks.json` issue | `next_action` | `JsonAdapter.create/update` payload |
| `tasks.json` issue | `title` | `JsonAdapter.create/update` payload |
| `tasks.json` epic | `title` | `JsonAdapter.createEpic/updateEpic` payload |
| LifecycleEvent `reviewer_report` | `notes` | `reportReviewer` payload |
| LifecycleEvent `validator_report` | `notes` | `reportValidator` payload |
| LifecycleEvent `step_failed` | `error` | `reportStep`/fold synthesis |
| LifecycleEvent `plan_task` | `notes` | `reportPlanTask` payload |
| LifecycleEvent `debug_intervention` | `note` | `reportIntervention` payload |
| LifecycleEvent `manual_override` | `reason` | manual operator JSONL write |
| StateProjection | `currentTask` (when set to a non-numeric label) | derived from above |

### Escaping rules

For each field listed above, the renderer applies the following transforms **in order** before interpolation:

1. **Newline normalization.** Replace any `\r\n` or `\r` sequence with `\n`. This is a structural cleanup before the next step.
2. **Inline-context newline collapse.** When the field is interpolated into a **single-line markdown slot** (a table cell, a list item header like `- **Status:** <field>`, a quoted span like `> Reason: <field>`), every remaining `\n` is replaced with a single space. When the field is interpolated into a **block-context slot** (a fenced code block or a wholesale paragraph), `\n` is preserved.
3. **HTML escape.** Replace `&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`, `'` → `&#39;`. This prevents inline HTML from re-entering the rendered markdown when consumers transform the markdown through an HTML pipeline (the typical Claude Code render path includes a markdown-to-HTML stage for GitHub-flavored display).
4. **Markdown structural escape.** Escape the markdown control characters that can alter block structure when interpolated mid-line: backtick (`` ` `` → `` \` ``), pipe (`|` → `\|`, critical for table cells), backslash (`\` → `\\`, applied first to avoid double-escape), `*` (→ `\*`), `_` (→ `\_`), `[` and `]` (→ `\[` and `\]`), `(` and `)` (→ `\(` and `\)`), `#` (→ `\#`), and a leading `>` (→ `\>`). Escape is applied uniformly regardless of slot type — these characters have no benign content meaning inside the listed free-text fields.
5. **Length truncation.** Each field is truncated to a per-field cap with a `…[truncated]` marker appended when exceeded:
   - `title` (Issue, Epic): 200 codepoints
   - `next_action`: 500 codepoints
   - `notes` (Issue, plan-task, reviewer-report, validator-report): 2000 codepoints
   - `error` (step_failed): 2000 codepoints
   - `note` (debug_intervention): 500 codepoints
   - `reason` (manual_override): 2000 codepoints
   - `currentTask` (label form): 100 codepoints
6. **Null and undefined handling.** Fields that are `null`, `undefined`, or absent render as the placeholder `—` (em-dash). Empty-string `""` renders as the same placeholder. The renderer does NOT distinguish empty-string from null at the markdown layer; both signal "no value."

### Code-fence rendering rule

For block-context slots that render long free-text content (`reason`, `error`, multi-paragraph `notes`), the renderer wraps the escaped content in a fenced code block:

````
```
<escaped reason>
```
````

Inside a code fence, the HTML and markdown structural escapes from rules 3-4 are still applied — the fence provides visual containment, not security containment. (A malicious code-fence-closing payload `` ``` `` would be caught by rule 4's backtick escape.)

### Escaping does NOT apply to

- Internal identifiers (`spec`, `slug`, `id`, `epicId`, `parent_id`, `step`, `event`, `actor`, `reviewer`, `validator`, `plan`, `task_id`, `verdict`, `severity`, `status`) — these are constrained by allowlists at write time per the foundation specs. Renderer trusts them.
- Timestamps (`ts`, `updated`, `created`, `startedAt`, `updatedAt`) — ISO-8601 format, no escape needed.
- Path fields (`spec_ref`, `plan_ref`, `planRef`, `ref`) — emitted inside backtick spans which the renderer escapes via rule 4. Operators can click them in IDE renders.
- Numeric / boolean fields — JSON primitives, no escape needed.

## System Constitution Reference

- **Principle:** "Minimize external dependencies — prefer Node.js built-ins" — Applies because the renderer uses only `node:fs`, `node:path`, `node:crypto`, `JSON.parse`/`JSON.stringify`, and `fs.glob` (Node 22+) / a `readdir` + filter for older runtimes. No markdown / HTML library is introduced; the escape table is small enough to inline.

The skill `/adev:status` consumes this rendering layer to surface human-readable output, but no skill logic moves into the lib. `adev status --render` and `adev status --pipeline` are operator-on-demand CLI flags, not autonomous skill behavior.
- **Architecture Boundary (Autonomous):** "Refactoring within a module's boundaries" — Applies because the renderer lives inside the `agent-reliable-state-artifacts` module and produces presentation-only artifacts. No charter amendment is required.

## Visual Expectations

The rendered markdown is the only user-visible surface of this spec. Format expectations:

- **Rendered `tasks.md`** preserves today's table-based layout exactly so legacy readers and the markdown parser continue to work. Header comment marks it generated. Section order: epics first (table), then open issues (table grouped by epic_id), then closed issues (collapsed `<details>` block).
- **Rendered `<slug>.md`** (lifecycle markdown view) layout:
  - H1 heading: `# Lifecycle: <spec-basename>`
  - Metadata table: spec path, status, currentStep, currentTask, startedAt, updatedAt
  - "## Steps" section with one H3 per canonical step (`specify`, `review`, `plan`, `route`, `implement`, `validate`); each H3 contains a verdict line, aggregated_from list, and per-reviewer / per-validator details in a fenced sub-block
  - "## Plan Tasks" section (table of `task_id`, `status`, `notes`)
  - "## Interventions" section (bulleted list of `debug_intervention` events)
  - "## Unknown Events" section (collapsed `<details>` block) when `unknownEvents[]` is non-empty
  - Trailing footer: `<!-- regenerated from <slug>.jsonl on <timestamp> -->`
- **`adev status --pipeline` stdout table:** plain-text aligned columns; no ANSI color codes (CI-friendly). Header row, separator, one row per spec. Empty result prints `No specs found in .context-index/lifecycle-state/`.
- **Mobile / narrow terminal:** the `--pipeline` table truncates long spec paths to 40 chars with `…` ellipsis. The `<slug>.md` markdown is consumed by external markdown renderers (Claude Code, GitHub) which handle their own responsive layout.

## Preconditions

- The project has a `.context-index/` directory (created by `/adev:init`).
- The project has a `.context-index/manifest.yaml`. Path-containment defenses enforce this on every public call.
- `lib/lifecycle-state.mjs` exists with the foundation-spec exports (`currentState`, `appendEvent`, the `renderMarkdown` and `listLifecycleStates` signatures). This spec replaces the stub bodies of the latter two.
- `lib/issues/json-adapter.mjs` exists with the foundation-spec API (`list`, `listEpics`, `_read`).
- `lib/issues/markdown-parser.mjs` exists with `parseTasksMd(contents) → board` (extracted per `json-issue-board-adapter.spec.md` SA-3). Round-trip property tests against `renderTasksMd` consume it.
- `lib/issues/resolve-root.mjs` exports `resolveStorageRoot()`.
- `lib/build-state.mjs::atomicWriteJson` is the atomic-write reference (renderer mirrors the pattern for markdown writes).
- `cli/index.mjs` exposes an `adev status` subcommand to which `--render` and `--pipeline` flags can be attached.
- Node.js runtime with `node:fs`, `node:path`, `node:crypto`, `JSON.parse`, `JSON.stringify` available.

## Behaviors

- **When** `renderTasksMd(board)` is called with a parsed `tasks.json` document **then** the function returns a string containing the generated-header comment followed by the table-based `tasks.md` layout that satisfies `parseTasksMd(returnedString) ≡ board`. The function is pure — no I/O, no side effects.
- **When** `writeTasksMd(projectRoot)` is called **then** it loads the board via `JsonAdapter.list()` + `JsonAdapter.listEpics()`, calls `renderTasksMd(board)`, and writes the result to `<storageRoot>/.context-index/tasks/tasks.md` via atomic temp-then-rename.
- **When** `renderMarkdown(state)` is called with a `StateProjection` **then** it returns a string conforming to the per-spec markdown layout in Visual Expectations, beginning with the generated-header comment and ending with the trailing regeneration-timestamp footer. Pure function; no I/O.
- **When** `listLifecycleStates(projectRoot)` is called **then** it globs `<projectRoot>/.context-index/lifecycle-state/*.jsonl`, folds each via `currentState`, returns one record per file as `{ spec, slug, status, currentStep, updated }`. Order is stable (lexicographic by slug) for deterministic output.
- **When** `listLifecycleStates` encounters a file whose stem fails the `[a-z0-9._-]+` allowlist **then** the file is skipped, a `SKIPPED_INVALID_SLUG` console warning is emitted with the offending stem, and aggregation continues.
- **When** `listLifecycleStates` encounters a malformed `<slug>.jsonl` (caught by `currentState`) **then** the file is skipped, a `MALFORMED_FILE_SKIPPED` console warning is emitted, and aggregation continues (matches the foundation spec's tolerance contract).
- **When** `listLifecycleStates` is called and the `.context-index/lifecycle-state/` directory does not exist **then** the function returns `[]` (no error thrown).
- **When** any escapable free-text field is rendered **then** the 6-rule escape pipeline is applied in order: newline normalization → slot-context newline collapse → HTML escape → markdown structural escape → length truncation → null placeholder. The rules are non-commutative (HTML escape must precede markdown escape so `<` doesn't get double-escaped). Test fixtures exercise each rule independently.
- **When** any escapable field is `null`, `undefined`, or `""` **then** the renderer interpolates the em-dash placeholder `—`. No distinction between empty-string and null at the markdown layer.
- **When** any escapable field exceeds its per-field cap **then** it is truncated to the cap (codepoint-counted, Unicode-safe) with `…[truncated]` appended. The cap applies after escape — the truncation operates on the escaped form so an attacker-crafted backslash-bomb cannot defeat the cap.
- **When** `adev status --render` runs **then** the CLI invokes `writeTasksMd(projectRoot)` once, then iterates `<projectRoot>/.context-index/lifecycle-state/*.jsonl` and writes each `<slug>.md` via atomic temp-then-rename. Per-file action summary is printed to stdout. Exit 0 on success.
- **When** `adev status --render` encounters an oversized `<slug>.jsonl` (> 50 MB) **then** the file is skipped with `OVERSIZED_LOG_SKIPPED` advisory; rendering continues for sibling slugs.
- **When** `adev status --pipeline` runs **then** the CLI calls `listLifecycleStates(projectRoot)`, prints a plain-text aligned table to stdout (columns: `Spec`, `Status`, `Current Step`, `Updated`), and exits 0 regardless of whether the result is empty.
- **When** both `--render` and `--pipeline` are passed **then** the render runs first, followed by a divider line, then the pipeline output. Both share a single exit code (1 if either fails, 0 otherwise).
- **When** any caller hand-edits a rendered `tasks.md` or `<slug>.md` **then** the next `adev status --render` invocation overwrites the edits unconditionally. The generated-header comment explicitly warns of this. No effect on the authoritative `tasks.json` / `<slug>.jsonl`.
- **When** a `projectRoot` does not resolve to a directory containing `.context-index/manifest.yaml` **then** `INVALID_PROJECT_ROOT` is thrown before any I/O occurs.
- **When** any resolved read or write path falls outside the applicable `.context-index/` scope (realpath-prefix check) **then** `INVALID_STORAGE_PATH` is thrown before the file is opened.
- **When** an atomic write fails at the rename step **then** the temp file is best-effort unlinked, the underlying `fs` error is rethrown, and the rendered file is left in its prior state.
- **When** any caller writes to a rendered markdown file via a non-atomic path **then** a CI architectural test catches it and fails the build.
- **When** any `SKILL.md` invokes `adev status --render` autonomously **then** a CI architectural grep test fails. Render is operator-on-demand only.

## Postconditions

- After a successful `writeTasksMd(projectRoot)`, the resolved target file contains a syntactically valid markdown document beginning with the generated-header comment. `parseTasksMd` round-trips it.
- After a rejected render (validation throw before write), the rendered files are byte-for-byte identical to their pre-call state. No partial-write state exists.
- After a `writeTasksMd` / `<slug>.md` write failure, no temp file from that operation remains on disk (best-effort cleanup).
- After `renderTasksMd` or `renderMarkdown` returns, the returned string is independent of any future state changes — subsequent writes do not mutate prior return values (pure functions).
- After `listLifecycleStates`, each record reflects the current state at glob time; entries are not memoised.
- After `adev status --render`, every `.context-index/lifecycle-state/<slug>.jsonl` whose stem matches the allowlist has a sibling `<slug>.md` updated to reflect the current fold. Files outside the allowlist or oversized are skipped per advisories.
- After `adev status --pipeline`, no files have been modified, created, or deleted. The command is read-only.
- After any hand-edit to a rendered file, the next `adev status --render` overwrites the edits and consumers reading the authoritative state are unaffected.

## Error Cases

| Condition | Expected Behavior | Error Code |
|-----------|-------------------|------------|
| Any public function called with a `projectRoot` lacking `.context-index/manifest.yaml` | Throws `INVALID_PROJECT_ROOT` with the resolved path | INVALID_PROJECT_ROOT |
| Any resolved read or write path falls outside the applicable `.context-index/` scope | Throws `INVALID_STORAGE_PATH` before the file is opened (realpath-prefix containment) | INVALID_STORAGE_PATH |
| `tasks.db_path` is set but does not resolve to a real existing directory | Throws `INVALID_STORAGE_PATH` (inherits from `milestones-migration.spec.md` rev 2) | INVALID_STORAGE_PATH |
| `<slug>.jsonl` filename stem fails the `[a-z0-9._-]+` allowlist during `--render` | Skip file, emit `SKIPPED_INVALID_SLUG` console warning, continue with remaining files | SKIPPED_INVALID_SLUG (warning) |
| `<slug>.jsonl` exceeds the 50 MB defensive cap | Skip render for that slug, emit `OVERSIZED_LOG_SKIPPED` advisory naming the slug, continue with siblings | OVERSIZED_LOG_SKIPPED (warning) |
| `<slug>.jsonl` is malformed (parse error during `currentState` fold) | Skip file, emit `MALFORMED_FILE_SKIPPED` console warning, continue (inherits from `lifecycle-event-log.spec.md`) | MALFORMED_FILE_SKIPPED (warning) |
| `tasks.json` is malformed (caught by `JsonAdapter._read`) | `writeTasksMd` propagates the underlying `MALFORMED_BOARD` error (matches `json-issue-board-adapter.spec.md`); render aborts; exit 1 | MALFORMED_BOARD |
| Atomic write rename fails (`EACCES`, `ENOSPC`, etc.) | Best-effort `fs.unlinkSync` on temp file, then rethrow underlying `fs` error code unchanged; rendered file remains in prior state | FS_ERROR |
| Atomic write temp-file write fails | Propagate `fs` error; no rename attempted; rendered file unchanged | FS_ERROR |
| `renderTasksMd(board)` called with a board missing required top-level keys (`version`, `epics`, `issues`) | Throws `INVALID_BOARD_SHAPE` (matches `json-issue-board-adapter.spec.md` Error Cases) | INVALID_BOARD_SHAPE |
| `renderMarkdown(state)` called with a non-`StateProjection` (missing `spec` / `status` / `steps` / etc.) | Throws `INVALID_STATE_PROJECTION` with a descriptor of which key is missing | INVALID_STATE_PROJECTION |
| Free-text field length exceeds the per-field cap | Truncate with `…[truncated]` marker appended to the escaped form; do not throw | — (no error) |
| Free-text field is `null` / `undefined` / `""` | Render the em-dash placeholder `—`; do not throw | — (no error) |
| Any caller writes to a rendered markdown file via a non-atomic-write path | CI architectural test fails the build | ARCH_VIOLATION_DIRECT_RENDER_WRITE |
| Any `SKILL.md` invokes `adev status --render` autonomously | CI architectural grep test fails the build | ARCH_VIOLATION_AUTONOMOUS_RENDER |
| `renderMarkdown` source contains an import of `lib/domains/domain-config.mjs` | CI architectural test fails the build (render is pre-stamped-severity-only; no domain config at render time) | ARCH_VIOLATION_RENDER_TIME_DOMAIN_CONFIG |
| CLI invoked with `--render` AND `--pipeline` together | Run render first, then pipeline; not an error | — (no error) |
| CLI invoked with neither `--render` nor `--pipeline` | Print existing `adev status` output (unchanged behavior); the two new flags are additive only | — (no error; pre-existing behavior) |
