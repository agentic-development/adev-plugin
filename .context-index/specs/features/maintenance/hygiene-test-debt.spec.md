# Live Spec: Test-Debt Audit Pass for /adev:hygiene

<!-- Live Spec within the maintenance charter.
     Parent Charter: .context-index/specs/features/maintenance/charter.md -->

## Context and Motivation

The 2026-08-10 three-repo audit found that no `/adev:hygiene` pass inspects the test
suite, and that `/adev:codehealth` cannot surface test debt **by construction** — its
detection-passes contract excludes every path matching `hygiene.coverage_exclude` (which
is `tests/**` in this repo) from orphan and dead-export detection. Test debt is therefore
invisible to the entire adev lifecycle today.

The audit observed five concrete debt shapes across the three repos. This spec turns
those five observations into a single advisory hygiene pass.

### Charter reconciliation (scope decision)

The `maintenance` charter is stale: it claims *"adev:hygiene — 11 audit passes"* while
the skill ships 22, it carries an unremoved `<!-- DRAFT: Generated by /adev:init -->`
banner, and it has no Capability Map. Three options were considered:

- **(a)** Retro-spec all 22 shipped passes and rewrite the charter to match.
- **(b)** Spec only the new pass and leave the charter drift to a separate work item.
- **(c)** Reconcile the charter's *factual claims* and its ownership model as part of
  this work, without retro-speccing the 22 existing passes.

**This spec adopts (c).** Rationale: (a) is a multi-day archaeology exercise that would
swamp a single advisory pass and would require reverse-engineering intent from 22 pass
bodies written across a year; (b) means knowingly adding pass #23 to a charter that
asserts 11, compounding the exact drift hygiene exists to catch. (c) is bounded: remove
the false count, drop the DRAFT banner, add a Capability Map, and record the ownership
rule that per-pass behavioral specs live under the charter that owns the *subject matter*
(precedent: `lifecycle-artifacts/hygiene-kind-validity.spec.md`,
`codehealth/hygiene-integration.spec.md`) with `maintenance` owning the skill shell.

**Explicitly NOT closed by this spec** and handed to a human: 20 of the 22 shipped
hygiene passes still have no behavioral spec of any kind. That is a real, pre-existing
gap. This spec records it; it does not fix it.

## Behavioral Contract

A new advisory audit pass — **Audit Pass 23: Test Debt** — surfaces five categories of
test-suite debt. The pass is *detection and reporting only*: it never edits, deletes, or
rewrites a test file, and it never blocks.

### Preconditions

- `.context-index/` exists and `manifest.yaml` is readable (a missing or unparseable
  manifest degrades to built-in defaults, it does not fail the pass).
- The project has at least one directory matching the configured test globs. A project
  with no tests yields a `SKIP` verdict, not a failure.
- The pass is driven by the CLI verb `adev test-debt scan`; `skills/hygiene/SKILL.md`
  names the verb and contains no inline Node (`cli-driver-surface` charter).

### Detectors

| Code | Signal | Default threshold | Severity |
|---|---|---|---|
| `APPEND_CHAIN` | ≥ N distinct test files reference the same source module | `append_chain_threshold: 4` | `warn` |
| `REV_NUMBERED` | Test basename matches `(^\|[._-])rev\d+([._-]\|$)` or `(^\|[._-])v\d+([._-]\|$)` | — | `warn` |
| `PLAN_TASK_STRUCTURED` | A test-title line contains `plan-task <N>` or `Task <N>` | ≥ 1 occurrence | `warn` |
| `DEAD_TEST_REFERENCE` | A test references a source path under `hygiene.source_roots` that does not exist on disk | — | `error` |
| `PROSE_ASSERTION` | Test references `.md` file paths AND the containment-assertion ratio meets the threshold | `prose_ratio_threshold: 0.5` | `info` |

**Severity is triage priority only.** Consistent with the Layer-1 posture established by
Audit Pass 18 (Kind Validity), no code emitted by this pass gates the hygiene exit code,
and `error` does not mean "blocking" — it means "look at this first".

### Reference extraction (shared by `APPEND_CHAIN` and `DEAD_TEST_REFERENCE`)

Both detectors consume one extraction pass. References are read **only from
reference-bearing syntactic positions**, never from arbitrary quoted strings — this is
the single most important precision decision in the spec, because test suites are full of
string literals naming fixture paths that intentionally do not exist:

- ESM: `from "<path>"`, `import("<path>")`
- CJS: `require("<path>")`
- Python: `import a.b`, `from a.b import ...`
- Subprocess: a quoted argument ending in a known source extension inside a
  `spawn` / `execFile` / `execSync` / `subprocess.run` / `subprocess.check_output` call

Relative paths resolve against the test file's directory, then normalise to
project-root-relative. Python dotted modules resolve to `a/b.py` probed under
`hygiene.source_roots`. A reference that resolves outside the project root is discarded.

### Behaviors

1. **When** `adev test-debt scan` runs in a project whose manifest declares
   `hygiene.source_roots` **then** it discovers test files via `hygiene.test_debt.test_globs`
   (default: `**/*.test.{mjs,js,ts,tsx}`, `**/*_test.{go,py}`, `**/test_*.py`,
   `**/*.spec.{js,ts}`), skipping anything matching `hygiene.test_debt.exclude` and any
   path under `node_modules/`, `.git/`, or `dist/`.
2. **When** ≥ `append_chain_threshold` distinct test files reference the same
   project-root-relative source module **then** the pass emits one `APPEND_CHAIN` finding
   naming that module, the count, and the participating test files (capped at 10 listed
   files with an `… and N more` suffix).
3. **When** a discovered test file's basename matches the rev-numbering pattern **then**
   the pass emits one `REV_NUMBERED` finding for that file.
4. **When** a line in a test file both (i) begins a test declaration
   (`describe(`, `it(`, `test(`, `def test_`) and (ii) contains a literal `plan-task <N>`
   or `Task <N>` **then** the pass emits one `PLAN_TASK_STRUCTURED` finding per file,
   carrying the occurrence count and the first three matched titles.
5. **When** a reference extracted from a test resolves under a configured source root but
   no file exists at that path **then** the pass emits a `DEAD_TEST_REFERENCE` finding
   naming the test file and the missing target.
6. **When** a test file references at least one `.md` path AND its ratio of
   containment-style assertions (`.includes(`, `.match(`, `toContain`, `assertIn`,
   `assert … in `) to total assertion lines is ≥ `prose_ratio_threshold` **then** the pass
   emits one `PROSE_ASSERTION` finding carrying the ratio and both counts.
7. **When** the pass completes **then** it returns
   `{ findings, summary, headerNotes, scannedFileCount }` and never throws, never mutates
   `process.exitCode`, and never writes to any file it scanned.
8. **When** `--json` is passed **then** the verb prints the result object as a single JSON
   document on stdout and nothing else; otherwise it prints a human-readable table
   grouped by detector code.
9. **When** `--detector <code>` is passed **then** only that detector runs; an unknown
   code exits 1 with `UNKNOWN_DETECTOR` and lists the five valid codes.
10. **When** `/adev:hygiene` runs a full audit **then** Audit Pass 23 appears in the
    summary table as `Test Debt` with `PASS` (zero findings), `WARN` (≥ 1 finding), or
    `SKIP` (no test files discovered).
11. **When** the project declares `hygiene.test_debt.enabled: false` **then** the pass
    reports `SKIP` with the reason `disabled by manifest` and emits no findings.

### Postconditions

- No file under any test glob is created, modified, or deleted by the pass.
- The issue board is not written to. Findings are report-only.
- The verb's exit code is `0` for any successful scan regardless of finding count.

### Error Cases

| Condition | Expected Behavior | Error Code |
|---|---|---|
| `.context-index/manifest.yaml` missing or unparseable | Scan proceeds with built-in defaults; a `headerNote` records the degrade | — (exit 0) |
| `hygiene.source_roots` absent | `DEAD_TEST_REFERENCE` and `APPEND_CHAIN` module attribution are skipped; `headerNote` records it; other three detectors still run | — (exit 0) |
| A test file is unreadable (permissions, binary) | File is skipped; a `headerNote` names it; scan continues | — (exit 0) |
| `--root` resolves outside the project root | Refuse before any read | `PATH_OUTSIDE_ROOT` (exit 1) |
| `--detector <code>` not in the closed enumeration | Refuse; list the five valid codes | `UNKNOWN_DETECTOR` (exit 1) |
| `append_chain_threshold` / `prose_ratio_threshold` non-numeric or ≤ 0 | Refuse; name the offending manifest key | `INVALID_TEST_DEBT_CONFIG` (exit 1) |
| No test files discovered | `SKIP` verdict with `scannedFileCount: 0` | — (exit 0) |

## Precision and False-Positive Posture

These are **heuristics**, and the spec says so plainly rather than implying detection is
sound. Expected precision, and what a false positive costs:

| Code | Expected precision | Dominant false-positive class | Cost of a false positive |
|---|---|---|---|
| `APPEND_CHAIN` | High (~0.9) — structural, derived from real import edges, not names | A genuinely large module with legitimately partitioned suites (e.g. adapter + contract + regression) | Reviewer reads a cluster and decides it is fine. Cheap. |
| `REV_NUMBERED` | Low–medium (~0.5) — pure filename pattern | Files legitimately versioned against an external schema or wire protocol (`payload-v1`) | Reviewer dismisses one filename. Cheap, but noisy at scale, which is why `v\d+` is separable from `rev\d+` in config. |
| `PLAN_TASK_STRUCTURED` | Medium (~0.7) — name pattern, but a very specific one | A test legitimately describing a domain object literally called "Task 3" | Reviewer dismisses. Cheap. |
| `DEAD_TEST_REFERENCE` | Medium–high (~0.8) — restricted to reference-bearing positions | Dynamically constructed paths; a module intentionally created at test runtime | Reviewer chases a non-bug. Moderate — this is the costliest FP, which is why extraction refuses arbitrary string literals. |
| `PROSE_ASSERTION` | Medium (~0.6) — ratio heuristic on assertion shape | A test that legitimately asserts on generated markdown output (renderers, report writers) | Reviewer dismisses; risk of the *aggregate number* being over-read as a quality verdict. |

**Non-overclaim clauses, binding on the implementation:**

- The pass MUST NOT describe a finding as a defect. Report language is "candidate",
  "review", "cluster" — never "broken", "dead test", "must fix".
- The pass MUST NOT produce a single composite "test debt score". Aggregating five
  heuristics of differing precision into one number would present false confidence.
- `PROSE_ASSERTION` is `info` severity precisely because its aggregate count is the
  easiest number in this spec to misread.
- Hygiene is advisory by design — it reports, it does not block. That is the correct home
  for heuristics of this precision, and none of these codes may ever be promoted to a
  gate without a follow-up spec.

## System Constitution Reference

- **Principle:** "Minimize external dependencies — prefer Node.js built-ins" — Applies:
  all discovery, extraction, and matching use `node:fs`, `node:path`, and `RegExp`. No
  glob or AST library is introduced; globbing is a hand-rolled matcher over `readdirSync`.
- **Principle:** "Skills are primarily markdown / no executable logic inside SKILL.md" —
  Applies: Pass 23's SKILL.md body names `adev test-debt scan` and renders the result. All
  control flow lives in `lib/hygiene/test-debt.mjs`.
- **Principle:** "Pure ESM" — Applies: new modules are `.mjs`.
- **Principle:** "Updating specs/ADRs when code changes affect their assumptions is
  required, not optional" — Applies directly: the charter reconciliation above is part of
  this spec's deliverable, not an optional extra.

## Acceptance Criteria

- [ ] `adev test-debt scan` exists, is registered in `cli/index.mjs`, and exits 0 on a
      clean scan and on a scan with findings.
- [ ] All five detector codes are implemented and individually selectable via `--detector`.
- [ ] The pass never writes to, deletes, or rewrites any scanned test file.
- [ ] Running the pass against this repository produces non-zero findings for
      `APPEND_CHAIN`, `PLAN_TASK_STRUCTURED`, and `PROSE_ASSERTION`, and the observed
      numbers are recorded in the validation report (dogfood requirement — a zero result
      is evidence the detection is wrong, not evidence the repo is clean).
- [ ] `skills/hygiene/SKILL.md` documents Audit Pass 23, updates its pass count to 23, and
      contains no inline Node (the `.githooks/pre-commit-no-inline-node` hook passes).
- [ ] `maintenance/charter.md` no longer claims 11 audit passes and carries a Capability Map.
- [ ] Manifest keys `hygiene.test_debt.*` are optional; absent config yields defaults.
- [ ] The report contains no composite score and no defect-asserting language.
- [ ] All quality gates pass (`npm test`, full suite).
- [ ] No constitutional violations introduced.
