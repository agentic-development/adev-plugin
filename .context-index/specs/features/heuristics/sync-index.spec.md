## Behavioral Contract

### Preconditions

- `/adev:sync` skill is functional (Setup module, validated)
- `lib/heuristics.mjs` is importable with `retrieveHeuristics` and `renderHeuristic` available
- `.context-index/manifest.yaml` contains `sync.targets` list
- The `tier` parameter on `retrieveHeuristics` is implemented (depends on keyword-tags-and-tiered-retrieval spec)

### Behaviors

1. **When** `/adev:sync` runs and high-confidence heuristics exist in the store **then** a `## Learned Lessons` section is appended to each sync target, placed after the `## Context Index` section but before the `# User Additions` marker.

2. **When** no high-confidence heuristics exist in the store **then** the `## Learned Lessons` section is omitted entirely from sync targets. No empty section header is written.

3. **When** a `## Learned Lessons` section already exists in a sync target **then** the existing section is replaced with the freshly generated index. The section is not duplicated.

4. **When** rendering the index **then** each heuristic entry is one line using the `index` tier format: `- <title> (<scope>) — <pattern summary>` where the pattern summary is truncated to 80 characters with ellipsis if longer.

5. **When** heuristics span multiple scopes **then** entries are grouped by scope, with scopes sorted alphabetically. A blank line separates each scope group. The `_global` scope sorts last (after all module scopes).

6. **When** the heuristic store is empty or contains only `low`/`medium`-confidence entries **then** no `## Learned Lessons` section appears. If a previous sync had written one, it is removed on the next sync.

7. **When** the sync target format is `claude` (CLAUDE.md) **then** the section is placed immediately before the `# User Additions` marker, after all other generated sections (including `## Task Management` if present). User Additions content below the marker is preserved unchanged.

8. **When** the sync target format is `opencode` (AGENTS.md) **then** the section is placed immediately before the `# User Additions` marker (or at the end of the synced content if no marker exists), after all other generated sections including `## Task Management`.

9. **When** the sync target format is `cursor` (.cursorrules) or `copilot` (copilot-instructions.md) **then** the section is appended at the end of the synced content. On re-sync, the replacement algorithm detects the `## Learned Lessons` heading and removes everything from that heading to the next `##` heading or EOF, then writes the fresh section in its place.

10. **When** `retrieveHeuristics` fails during sync (e.g., malformed heuristic file) **then** the sync proceeds without the `## Learned Lessons` section. A warning is printed but sync does not fail.

### Postconditions

- All sync targets contain an up-to-date heuristic index reflecting the current high-confidence entries
- User Additions content in CLAUDE.md is never modified or lost
- Sync targets without a previous `## Learned Lessons` section gain one if high-confidence heuristics exist
- Sync targets with a stale `## Learned Lessons` section are updated to current state

### Error Cases

| Condition | Expected Behavior | Error Code |
|-----------|-------------------|------------|
| Heuristic store directory missing | Skip Learned Lessons section, no error | N/A |
| `retrieveHeuristics` throws | Skip Learned Lessons section, print warning | N/A |
| Sync target file not writable | Existing sync error handling applies | N/A |
| Malformed heuristic file in store | `readHeuristics` skips malformed entries (Phase 1 behavior) | N/A |

## System Constitution Reference

- **Principle 2:** "Skills are primarily markdown" — The sync index is generated by the `/adev:sync` skill (markdown). The rendering logic lives in `lib/heuristics.mjs` as companion code.
- **Principle 1:** "Minimize external dependencies" — Uses existing `retrieveHeuristics` with `tier: 'index'` and string truncation. No new dependencies.
